# claude-plus-fa: limit fallback

What is true now; history in [`trials.md`](../trials.md). Limits of this feature stay in `memory.md` § Limits.

## The way out
- The dialog opens on every rate-limit stop; only a session already on a gateway (`ANTHROPIC_BASE_URL` set) stays silent, so GLM never relaunches itself. The hook waits inside itself (timeout 3600 s).
- Window: pywebview + WebView2 with the panel's Spark tokens, 540 px, title *Usage Limit Reached: <folder>*, an X, an amber note on what leaves the machine ("GLM sends the conversation so far to z.ai; Codex sends it to OpenAI"), then *Cancel*, the GLM button and the Codex button, equally wide. Escape, X and Cancel mean no; the first ready Continue button has the focus; it takes the foreground with a lone Alt press.
- Brand line above the title: the `asking-purple` strip at 28 px (550 ms a frame, frame 0 under reduced motion) and `claude-plus-fa` in 12 px muted semibold; strips from `~/.claude/agent-panel-mascot`, else the repo's `mascot/`, inlined as data URLs; without either, the name alone.
- The window is sized to its content before it shows and after every change, one resize at a time (`fit()` chained); `main` keeps its natural height.
- Each option is ready (*Continue With GLM* / *Continue With Codex*, blue) or not (*Set Up GLM* / *Set Up Codex*, white); Set Up shows its steps in the body, one at a time, a second click hides them.
- GLM steps: sign up at `z.ai/model-api`, create a key at `z.ai/manage-apikey/apikey-list`, *Open Key File* (opens the key file in Notepad, creating it with the placeholder).
- Codex steps, each a button running in its own console, shown *Done* once true: *Install* (`npm install -g @openai/codex`; without npm a link to nodejs.org), *Add Plugin* (`claude plugin marketplace add openai/codex-plugin-cc && claude plugin install codex@openai-codex`), *Sign In* (`codex login`; the dialog never handles credentials).
- The page asks `state()` every 2 s. GLM ready = a real key in the file (never shown or logged). Codex ready = `codex` and `node` on PATH, `codex@openai-codex` in `installed_plugins.json` with a `codex-companion.mjs` in its newest cached version (`companion()`, versions sorted numerically), and `codex login status` exiting 0.
- GLM: `cmd /k glm --resume <sid> [--dangerously-skip-permissions] "<continue prompt>"` in the session's cwd, in its own titled window as for Codex (`open_glm()`, `open_window()`, its `cmd.exe` found by the session id). The skip flag is added when the hook input's `permission_mode` is `bypassPermissions` or missing. GLM is Claude Code, so it loads the global and the project's CLAUDE.md itself (checked: `glm -p` named the project CLAUDE.md's code word and a rule of the global one without tools); its prompt adds only the old window's work, when there is any (`kept_open()`).
- Codex: the window shows *Moving the conversation to Codex...* with its buttons off; a failure shows in red (*Could not move it to Codex: <reason>*) and the user can pick again; on success `cmd /k codex resume <thread> -c tui.terminal_title=['thread-name'] [--dangerously-bypass-approvals-and-sandbox] "<continue prompt>"` opens in the cwd (`open_codex()`, `open_window()`).
- Its window: with Windows Terminal (`wt` on PATH) `wt -w new new-tab --title "<name>" --suppressApplicationTitle -d <cwd> cmd /k ...` (a new window; `;` escaped as `\;`); its `cmd.exe` is found by the thread id in its command line (`cmdline()`, `NtQueryInformationProcess`), born after the launch, within 15 s (`Console`; not found: pid `None`, and no second window). Without it `cmd /k title <name>& ...` in a new console. Either way the environment has no `CLAUDE*`, `ANTHROPIC*`, `CODEX_COMPANION*` (`glm.cmd` sets its own `ANTHROPIC*`). Codex titles its terminal `<thread name> | <folder>` by default, hence the `-c`; Claude Code (GLM) titles it `<status glyph> <name>`, kept out by the pinned title under Windows Terminal, not without it.
- `<name>` = `session_name()`: what the panel's card shows (last `custom-title`, else last `ai-title`, else the first real prompt; the same reading as the panel's `parse()`), else the folder; `window_name()` drops `&|<>^"%`, 80 characters at most.
- Before the window opens, `name_thread()` names the Codex thread the same, the way Codex's `/rename` does: `codex app-server` (stdio) `initialize`, `initialized`, `thread/name/set {threadId, name}` (30 s). It writes `~/.codex/session_index.jsonl` and the thread's `title` in `state_5.sqlite`; Codex's footer shows it and Codex does not rename it on the first turn (Codex CLI 0.164.0 and 0.171.0).
- `codex_prompt()` adds: read `~/.claude/CLAUDE.md`, `<cwd>/CLAUDE.md` and `<cwd>/.claude/CLAUDE.md` (those that exist) and follow them as Claude Code would, above all their documentation rules; and, when the old Claude window still runs work, that it stays open until that has ended. One line; `"`, `%` and line breaks removed.
- `transfer()` runs the plugin's `node codex-companion.mjs transfer --source <transcript> --json` (no Claude model needed), then reads `~/.codex/external_agent_session_imports.json` itself (`imported_thread()`: path without the `\\?\` prefix, case-insensitive, and the sha256 of the file handed over), since the plugin reports every Windows import as failed.
- Codex imports a path once, so a transcript that comes to Codex again, or a cut, goes as a copy in `<projects>/<folder>/<sid>/codex-transfer/<YYYY-MM-DD_HHMMSS>.jsonl` (inside the session's `<id>/` folder: not listed as a session; the panel's Delete takes it along). Codex's thread file: `~/.codex/sessions/YYYY/MM/DD/rollout-<time>-<thread>.jsonl` (`thread_file()`, `CODEX_HOME` respected).
- What Codex gets (`codex_cut()`, written by `write_cut()`; the transcript is only read): the last compact boundary, its summary, the messages that compaction preserved (`compactMetadata.preservedSegment`, chain from `tailUuid` to `headUuid`, nothing if broken) and everything after; over `CODEX_BUDGET` 100,000 tokens, the boundary, summary and the newest turns that fit, each from a typed prompt on; a last turn alone over the budget: its prompt and the newest lines that fit. No compaction and within budget: imported whole.
- Size is Codex's own measure, characters / 4 of what its import keeps (`codex_cost()`: user and assistant text and tool calls whole, tool results cut to `RESULT_MAX` 4000; thinking, images, attachments, meta and sidechain lines dropped; Codex CLI 0.164.0). After the import `imported_tokens()` reads Codex's `token_count`; above `CODEX_CEILING` 200,000 it cuts once more with the budget scaled down by the miss, then gives up with "The conversation is too long for Codex".
- When cut, the continue prompt adds that only the latest part was brought over and names the whole transcript's path (`codex_prompt()`).
- `first_turn_error()` watches Codex's first turn in the thread file for up to `WATCH` 180 s: a `task_complete` or `turn_aborted` with an `error`, or an `error` event, reopens the way-out window with a red line quoting Codex's message (`stopped_text()`); Cancel there keeps the Codex record. The model's first output (an assistant message, reasoning or a tool call), a good end, a closed window or the 180 s end the watch; the hook then writes `<sid>.watched` (`{thread, at}`, `mark_watched()`) and ends. After GLM it writes it at once, `thread` null; `record_switch()` deletes an earlier move's.
- Either way the hook then writes the way-back record. Without pywebview it falls back to a Win32 message box offering GLM alone (with a key).
- pywebview walks the js_api object's attributes, so the window lives in the module's `WIN` dict and the Api classes share `Base` (`fit`, `close`).
- Previews (no stdin, nothing sent, transferred or started, no Alt press): `python glm-fallback.py --preview [folder] [--glm on|off] [--codex ready|cli|plugin|login|none] [--open glm|codex] [--press glm|codex] [--fail] [--stopped]`; `--preview-return [folder] [GLM|Codex]` for the way-back dialog.

## The way back to Claude
- On Continue the hook writes `~/.claude/state/glm-return/<sid>.json`: `session`, `cwd`, `folder`, `via` (`glm`/`codex`), `console` (pid of the new `cmd /k`, `null` when not found; older records `glm_cmd`), `transcript`, `orig_pid` (the Claude process the limit stopped, looked up before GLM starts), `skip`, `at`, `resets_at`, `reset_from`; for Codex also `codex_thread`, `codex_file`, `codex_from` (thread size right after the import), `name`, `named`, `work` (what the old window ran at the move). The panel adds `agent_seen`, `_open`, `orig_idle`, `orig_used` (the old window turned busy after idle: typed into), `old_closed`, `old_work`, `auto_back`, `claude_cmd`, `switch_at`, `carry`, `go` and the question's `asker`, `asked`, `next_ask`, `no_more`.
- `resets_at` = `five_hour.resets_at` from `rate_limits.json`; a `seven_day` at 100 % resetting later wins; if neither is in the future, now + 5 h (`reset_from` = `estimate`).
- The panel runs `watch_return()` / `step_return()` on every 2 s live pass and after each scan (nothing, and no process snapshot, when the folder is empty). If the panel is not running the record waits.
- Step 1: after Continue or Back to Claude, once a process under the new Claude process holds the session, end the GLM/Codex tree and drop the record (a Codex turn written after the carry keeps it, for the `--carry` hook); after `START_WAIT` 90 s without that, or if it died, clear `claude_cmd` and `go`, give the Codex carry back (`give_back()`), keep the record.
- The old window (GLM and Codex): once GLM (a Claude process of the session) or Codex has been seen under its console, its window is open, `<sid>.watched` names the record's thread and the original Claude process is `idle` and was never typed into (`orig_used`), `close_old()` ends that window, unless `busy_work()` finds work (then `old_work`, looked at again every pass). It ends `console_root()` (the processes attached to its console, `AttachConsole` + `GetConsoleProcessList`, walked up from it: the tab's shell) with `end_tree()`; never an ancestor of the panel or of the GLM/Codex console. `old_closed` = when.
- `busy_work()` (in `glm-fallback.py`, used by the hook and the panel): subagent metas without `finished`/`stoppedByUser` written since the process started; Claude Code processes under it holding a session of their own; background commands: `running in background with ID: X` in the last `BG_TAIL` 4 MB after the process started, without a later `<task-id>X</task-id>` or `TaskStop` of X, and a child of the process born over `LATE` 20 s after it (not the hook's own chain). About 0.1 s on a 428 MB transcript.
- Step 2: a Claude window holds the session again (a process neither under the console nor the original, or the original typed into after being seen idle, `orig_used`): GLM record dropped; Codex record dropped once the Codex window is closed and nothing is left uncarried (`pending()`), kept until then. A record whose transcript is gone is dropped.
- Console gone, or GLM/Codex seen and gone (`agent_seen`: a Claude process of the session under the console for GLM, a `codex.exe` or `node.exe` under it for Codex): no question (`_open` false), an open question or pending Back to Claude ended. GLM or Codex seen, `<sid>.watched` or the old process gone, once per record (`auto_back`): the old window is closed first when idle without work, then `launch_back()` at once, reset or not (after GLM a plain `--model` resume, no prompt: GLM's turns are in the transcript). For Codex, before the reset it writes `<sid>.quiet` (`{until: resets_at}`) and the way-out hook stays silent for that session until then, so Claude Code's own "set to continue automatically" carries on. An old window still running work holds the session: nothing starts, and each pass looks again, so the return comes once the work ends (or a prompt typed there makes it the session's window: Codex's turns then come through `--carry`; GLM's record is dropped). If that Claude never takes the session, the card's Back to Claude remains.
- Step 3: read `<sid>.answer` (survives a panel restart; a dialog gone without one is Not Now).
- Step 4: wait for `resets_at` and `next_ask`, then for GLM/Codex idle `IDLE_FOR` 4 s, never cutting a turn. GLM idle: every GLM process of the session `idle`. Codex idle (`codex_idle()`): the last `task_started` after `codex_from` followed by `task_complete` or `turn_aborted`, and the file unwritten for 4 s.
- Step 5: ask (`pythonw glm-fallback.py --ask-return <answer file> <folder> <session title> <what Not Now does> [GLM|Codex]`, no console) or, after Continue, `resume_claude()`: `claude --resume <sid> --model <model>` (plus `--dangerously-skip-permissions` when the hook had it) in the record's folder. Model: the last `claude-*` model in the transcript (`claude_model()`), else `default`.
- From Codex the first prompt is the record (`codex_back_prompt()`): each user message, Codex reply, command with exit code (code mode's JavaScript reduced to its `exec_command` lines), files changed by patches, and files in the session folder written since the move (`.git`, `node_modules` and similar skipped, at most 100 named, 20000 visited), then "Continue from where Codex stopped." It goes to `claude.exe` as one argument of a new console (CreateProcess quoting carries newlines).
- A record over `PROMPT_MAX` 24000 characters is written whole to `<cwd>/codex-record_<YYYY-MM-DD_HHMM>.md` and the prompt carries its path and the last `TAIL` 12000 characters; a `claude` that is a `.cmd` (npm install) gets the file and a one-line prompt.
- Not Now: asked once more after `ASK_AGAIN` 30 min (only when idle); a second Not Now sets `no_more` and keeps the record; the dialog says which applies.
- The question is shown with `focus=False` and hands the foreground straight back: over every window, never taking the keyboard, answered by mouse; no Alt press.
- `end_tree()` closes the GLM/Codex window and the old Claude window: every process under its console, deepest first (a child older than its parent skipped as a reused pid), then the console with exit code 0 (Windows Terminal then closes the tab); never `WM_CLOSE`.
- The record lives until a Claude process holds the session again (for Codex: and its window is closed with nothing left uncarried) or the transcript is deleted. `<sid>.watched` goes with it; `<sid>.quiet` stays until its time passes; carry files outlive it (swept after `CLAIM_KEEP` 7 days once no record names the session). Cards say `on GLM` / `on Codex` in their flags (`self.returns` → `via`, `viaOpen`).
- While GLM/Codex still runs in its window (`_open`: console alive with matching `console_born`, and GLM/Codex seen under it or not yet seen), a click or double-click raises that window (`raise_return()`, second click minimises).
- Right-click menu has **Back to Claude** first. `back()` with the window open sets `go` (the next step goes back without waiting for the reset); mid-turn it answers "<GLM|Codex> is in the middle of a turn; it goes back to Claude as soon as that turn ends.", else "Going back to Claude…". With the window closed it resumes at once (`launch_back()`), as does a double-click.
- Every other card resume goes through `resume_cmd()`: `--model <claude_model()>` when the last assistant turn (skipping `<synthetic>`) is not `claude-*` (`resume_model()`).
- Codex's turns are carried incrementally: `<sid>.<thread>.carried` holds `{to, from, by, at, prev_at}`, `to` being the byte offset in the thread file up to which turns were carried (a file without `to`, from before 2026-11-21, counts as everything carried). `take_carry()` takes, under `<carry file>.lock` (`O_CREAT | O_EXCL`, 3 s, stale after 10 s), every complete line after `to` when they hold a user message, a reply, an abort, a patch or a tool call, and moves `to`; `give_back()` moves it back unless a later carry moved it on. `codex_back_prompt(rec, span=...)` builds the record of that span; a later carry starts "This session went on in Codex after the last record of it..." and lists files written since the previous carry.
- Carriers: the panel (`launch_back()`) and `glm-fallback.py --carry` (registered on `SessionStart` matcher `resume` and on `UserPromptSubmit`, timeout 30), which adds the record as `additionalContext`. A resume by hand carries what exists so far; a prompt carries only once the Codex window is closed (`codex_open()`: console alive with matching birth; a console not found counts as open). The hook never deletes the record.
- The panel loads `glm-fallback.py` as a module (`fallback()`) for these helpers.

## Codex's own traps
- Codex started without a prompt may update itself first (`npm install -g @openai/codex`, seen 0.164.0 to 0.171.0 on 2026-11-21) and close its window. A Codex TUI of another version than the running app-server daemon says "This conversation is open in another app" for a thread the daemon still holds (an older window's thread resumed again); a fresh import is not affected.
