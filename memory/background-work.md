# claude-plus-fa: background work and the opened card

What is true now; history in [`trials.md`](../trials.md).

## Background work badge
- An open session's card shows a turning arc and a count on its title row (`--surface2` on `--muted`, 16 px, before the age; in the tab on top); gone when nothing runs; arrow 1.6 s a turn (still under reduced motion). Closed sessions have none. It has no tooltip: its pieces are listed in the opened card. The card's `aria-label` ends with `bgSaid()` (*2 background runs, 3:10*).
- It counts child runs and subagents only; background commands are not counted (they would need a transcript read on every live pass), they appear only in the opened card.
- Background work turns the card's tint and ring green, as a working card's (`groupOf()`: an open session with `bg`, asking wins, closed never counts; same test as the conducting hero, `delegated()`); the dot keeps the session's own state (`stateOf()`). The time's place shows how long the work has run (`bgSince`, `Panel.bg_start()`) unless the session is itself working.
- Computed in `Panel.background()` on every live pass and scan from the Toolhelp snapshot `procs()`; it also keeps the session files of that pass in `Panel.live` for `peek()`.
- Child runs (`child_runs()`): processes that are Claude Code by full path (`~/.local/bin/claude.exe`, `claude.exe.old.*`, files under `~/.local/share/claude/versions/`; `QueryFullProcessImageNameW`) whose parent chain reaches an open session's pid, the nearest winning; each parent no younger than its child (`born()`); a process holding the same session id is not a run; a Claude Code process straight under another without a session of its own (`claude mcp serve`) is skipped. Folder from its session file; start from its own `claude.exe` creation time (`GetProcessTimes`). Each item also carries `pid`, its own session id `sid` and `cwd`.
- Subagents (`subagents()`): `<transcript folder>/<session id>/subagents[/<subfolder>]/agent-<id>.meta.json` without `finished` or `stoppedByUser`, written since the session's process started; walked with `os.scandir`, a meta re-read only when its mtime changes (`Panel.metas`); start from the agent's `.jsonl` creation time; the item carries that `.jsonl` as `file`, the meta's `toolUseId` as `use`, its `parentAgentId` as `parent` and, under `subagents/workflows/wf_<run>/`, the run as `wf` (`wf_run()`).
- Work without a start of its own takes the first read that saw it (`Panel.bg_seen`, forgotten once nothing runs).

## Opened card
- Resting the pointer on a card for `PEEK_WAIT` 500 ms after a real mouse movement opens it; moving across the list opens nothing. On the right dock and in the set-aside list the card itself grows downward (`.xp` inside the card, `.card:has(> .xp)` turns its height auto), so the cards below move down and the card stays where it is (`#list` has `overflow-anchor: none`); it opens and folds back in 160 ms (at once under reduced motion). A tab in the top strip has no list to push: the same content drops in a box under it (`.xbox`, 340 px, 6 px under the tab, centred on it, part of the window region).
- Content, nothing else: the work still running, grouped by the prompt the user typed that set it off, newest prompt first: the prompt (`.xh`: *Last Prompt* for the session's last, else *Earlier Prompt*; clamped to 3 lines, `.x3`), then one row per piece (`.xq`, indented 8 px, one line: name · description · time run, ticking: *45 s*, *14 min*, *2 h 5 min*, `lasted()`), oldest first; no task text. Names: subagents *Agent 1*, *Agent 2*, ... in start order per prompt group; one Workflow run's agents kept together where its first started, under one line *Workflow <name>* (`.xw`), numbered *Agent 1*, ... within the run and indented 16 px (`.xq.in`); *claude -p* and *Command* keep their kind and name. A run's name (`flow_name()`): the shared prefix when every label is `<name>:<rest>` (rows then show the rest), else the script file `<session>/workflows/scripts/<name>-<run>.js` (rows keep the label; cached in `peeks["flow"]`), else none (*Workflow* alone). The last prompt comes first, alone when it started nothing still running; work whose prompt was not found comes last under *Prompt not found*. Title, folder and state are not repeated (the card shows them; its `aria-label` holds the full title and folder). A session with no prompt and no work does not open.
- Size: up to `PEEK_MAX` 280 px, and in a list no further than the room left under the card in view (never under `PEEK_MIN` 96); rows that do not fit are dropped from the end, a prompt or *Workflow* line left without rows with them (never the first), and a last row *and n more* (blue) says how many pieces are left out.
- *and n more* opens the column of every piece of work running, grouped as above (only prompts with work), and closes it on a second click; the click reaches nothing else (a capture listener stops it before the card's own click and double click). Right dock: a window of its own (`agent-column.html`, title *Field Agents Column*, `COL_W` 300 px), right edge at the panel window's left edge, top at the card's top (`ClientToScreen` + card top x scale), as tall as the page measures (`col.fill(rows)`), at most to `COL_BELOW` 8 px above the work area's bottom, then it scrolls inside; a card lower than `COL_MIN` 120 px above the bottom moves it up so far. Made hidden at start, shown once off screen (`wake()`), then topmost with `SWP_NOACTIVATE | SWP_SHOWWINDOW`, rounded by a region; `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`. Top dock: an `.xbox.col` in the page, 300 px, left of the box (right of it when the screen has no room), top at the box's top, scrolling inside past the window's bottom.
- It closes when the pointer has left the card, its box and the column: at once from a right-dock card without a column, after `PEEK_GRACE` 250 ms otherwise (500 ms when it left the panel window with the column open), so the pointer can cross the gap. The column window reports enter and leave (`ColumnApi.hover` -> `app.col(on)`). Moving onto another card opens that one instead. Also closed by a key, a right-click, a list scroll, a resize, a drag, a dock change, and the window losing focus (hiding the panel hides the column); after a key or right-click it reopens only once the pointer has left that card. A press or click does not close it: a click on the card (opened part included) does what the card's click does.
- While a card is open the list keeps its order (`holdOrder()`); the waiting order comes in when it closes.
- `aria-hidden`, never focused, keys never prevented; the column window never activated.
- Data: the page calls `api().peek(id)` when it opens and again on every `app.update()` while open (content redrawn only when it changed); with the column open, also `api().column(id, top)`, which reads `peek()` again (cached) and refills and places the window; `api().column_off()` hides it. `Panel.peek(sid)` returns `{id, groups: [{prompt (None: not found), last, bg: [{kind, what, since ms, and for a Workflow's agent wf, flow}]}]}`, rows numbered and ordered by `arrange()`, or `None` for an unknown session; a closed session gets its last prompt only. Nothing is kept by the pages, written or logged.
- Readers (only for the opened card; caches in `Panel.peeks`):
  - `typed_prompt()`: a line is a prompt the user typed when it is a `user` line that is not meta, sidechain, a tool result, a tag such as `<task-notification>` or `<command-name>`, a compaction summary or an interruption, and whose `origin.kind` is absent or `human` (not `task-notification`, `peer`, `auto-continuation`); or an `attachment` of type `queued_command` (`commandMode` `prompt`, origin `human`): a prompt typed while Claude works. A `:N` reply's passages come in separate `hook_additional_context` attachment lines, never in the prompt line, so the prompt shows as typed.
  - `last_prompt()`: the last such line, `{id: uuid, text, at}`, searched in the last `PEEK_TAIL` 256 KB, then `PEEK_MORE` 4 MB; cached by (size, mtime).
  - Which prompt set a piece off: `chain_prompt(path, start)` reads the session's transcript from its end back (`back()`: `CHAIN_STEP` 4 MB at a time, whole lines only), finds the start line, then walks `parentUuid` (across a compaction `logicalParentUuid`) up to the first line `typed_prompt()` takes. Only lines holding `"uuid":"<id>"` (as bytes) are parsed, so a long chain costs a byte search; it stops `CHAIN_MAX` 256 MB from the end (transcripts reach 1.2 GB). A task notification in between is passed over, since it is not a typed prompt.
  - Start lines (they must carry a `uuid`: an `api-request-blob` line repeats a request's tool calls without one): a subagent (`agent_trigger()`): up its `parentAgentId` chain through the metas (`agent_meta()`, any depth, an agent's own transcript holds no typed prompt) to the agent the session started, then its `toolUseId` tool call (`call_of()`), or for a Workflow's agent the user line whose `toolUseResult.runId` is its run (`workflow_of()`); a command: its `tool_use` id from `bg_commands()`; a `claude -p` run (`run_trigger()`): the latest Bash/PowerShell call naming `claude` written at most `RUN_WAIT` 60 s before the process started (`shell_of()`), in the session's transcript or else in a running subagent's (then that agent's prompt).
  - `settled()` keeps each answer in `peeks["trig"]`: for good once found (or found missing); while the start line is not written yet, the end searched, so the next call reads only what came since. Siblings share one walk (key: the tool call or Workflow run).
  - `bg_commands()`: in the last `BG_TAIL` 4 MB, a `tool_use` with `run_in_background` (not Agent/Task) whose `tool_result` says `running in background with ID: X` at or after the process start, without a later `<task-id>X</task-id>` or a `TaskStop`/`KillShell` of X; cached by (size, mtime, start). Shown only when `late_child()` finds a child of the session's process born over `LATE` 20 s after it started. Same rule as `busy_work()` in `glm-fallback.py`.
  - `flat()`: whitespace collapsed, BOM removed, cut at `PEEK_CHARS` 1200 with `…`.
- Cost measured read-only on real sessions (450 MB, 900 MB, 1.2 GB): the prompt behind an agent found in 20 to 210 ms the first time, 0.02 ms after; `last_prompt()` under 10 ms.

## Limits
- Badge: no runs inside WSL, nor runs whose parent chain passes a process the panel cannot open (elevated); subagents read right only on versions that write `finished` (2.1.323 does; older versions would count every agent of the process as running); workflow agents' `finished` never seen; an agent resumed with SendMessage after it finished may not show. Background commands are not counted by the badge, only listed in the opened card, and only while a late child of the session's process exists; one started more than 4 MB back in the transcript is missed. A piece of work whose prompt lies over 256 MB back, or a `claude -p` launched by a command not naming `claude`, shows under *Prompt not found*. The opened card was checked in the page (Playwright), not by a real hover on the live panel; the column window's place on screen not seen live.
- A Workflow run whose agents' labels share no `<name>:` prefix and whose script file is not in the session's `workflows/scripts/` shows as *Workflow* without a name.
