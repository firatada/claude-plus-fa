# claude-plus-fa: background work and the opened card

What is true now; history in [`trials.md`](../trials.md). Limits of these features stay in `memory.md` § Limits.

## Background work badge
- An open session's card shows a turning arc and a count on its title row (`--surface2` on `--muted`, 16 px, before the age; in the tab on top); gone when nothing runs; arrow 1.6 s a turn (still under reduced motion). Closed sessions have none. It has no tooltip: its pieces are listed in the opened card. The card's `aria-label` ends with `bgSaid()` (*2 background runs, 3:10*).
- It counts child runs and subagents only; background commands are not counted (they would need a transcript read on every live pass), they appear only in the opened card.
- The session's own look (`stateOf()`) is unchanged by background work: dot and tint show only the session's own state; the hero conducts (memory.md, Mascot). The time's place shows how long the work has run (`bgSince`, `Panel.bg_start()`) unless the session is itself working.
- Computed in `Panel.background()` on every live pass and scan from the Toolhelp snapshot `procs()`; it also keeps the session files of that pass in `Panel.live` for `peek()`.
- Child runs (`child_runs()`): processes that are Claude Code by full path (`~/.local/bin/claude.exe`, `claude.exe.old.*`, files under `~/.local/share/claude/versions/`; `QueryFullProcessImageNameW`) whose parent chain reaches an open session's pid, the nearest winning; each parent no younger than its child (`born()`); a process holding the same session id is not a run; a Claude Code process straight under another without a session of its own (`claude mcp serve`) is skipped. Folder from its session file; start from its own `claude.exe` creation time (`GetProcessTimes`). Each item also carries `pid`, its own session id `sid` and `cwd`.
- Subagents (`subagents()`): `<transcript folder>/<session id>/subagents[/<subfolder>]/agent-<id>.meta.json` without `finished` or `stoppedByUser`, written since the session's process started; walked with `os.scandir`, a meta re-read only when its mtime changes (`Panel.metas`); start from the agent's `.jsonl` creation time; the item carries that `.jsonl` as `file`.
- Work without a start of its own takes the first read that saw it (`Panel.bg_seen`, forgotten once nothing runs).

## Opened card
- Resting the pointer on a card for `PEEK_WAIT` 500 ms after a real mouse movement opens it; moving across the list opens nothing. On the right dock and in the set-aside list the card itself grows downward (`.xp` inside the card, `.card:has(> .xp)` turns its height auto), so the cards below move down and the card stays where it is (`#list` has `overflow-anchor: none`); it opens and folds back in 160 ms (at once under reduced motion). A tab in the top strip has no list to push: the same content drops in a box under it (`.xbox`, 340 px, 6 px under the tab, centred on it, part of the window region).
- Content, nothing else: *Last Prompt* and the prompt; then one row per piece of work still running, oldest first: kind (*Subagent*, *claude -p*, *Command*) · description · time run (ticking), and what it works on now. Every prompt clamped to 3 lines (`.x3`). Title, folder and state are not repeated (the card shows them; its `aria-label` holds the full title and folder). A session with no prompt and no work does not open.
- Size: up to `PEEK_MAX` 280 px, and in a list no further than the room left under the card in view (never under `PEEK_MIN` 96); rows that do not fit are dropped from the end and a last row *and n more* (blue) says how many.
- *and n more* opens the column of every piece of work running, rows as above, and closes it on a second click; the click reaches nothing else (a capture listener stops it before the card's own click and double click). Right dock: a window of its own (`agent-column.html`, title *Field Agents Column*, `COL_W` 300 px), right edge at the panel window's left edge, top at the card's top (`ClientToScreen` + card top x scale), as tall as the page measures (`col.fill(rows)`), at most to `COL_BELOW` 8 px above the work area's bottom, then it scrolls inside; a card lower than `COL_MIN` 120 px above the bottom moves it up so far. Made hidden at start, shown once off screen (`wake()`), then topmost with `SWP_NOACTIVATE | SWP_SHOWWINDOW`, rounded by a region; `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`. Top dock: an `.xbox.col` in the page, 300 px, left of the box (right of it when the screen has no room), top at the box's top, scrolling inside past the window's bottom.
- It closes when the pointer has left the card, its box and the column: at once from a right-dock card without a column, after `PEEK_GRACE` 250 ms otherwise (500 ms when it left the panel window with the column open), so the pointer can cross the gap. The column window reports enter and leave (`ColumnApi.hover` -> `app.col(on)`). Moving onto another card opens that one instead. Also closed by a key, a right-click, a list scroll, a resize, a drag, a dock change, and the window losing focus (hiding the panel hides the column); after a key or right-click it reopens only once the pointer has left that card. A press or click does not close it: a click on the card (opened part included) does what the card's click does.
- While a card is open the list keeps its order (`holdOrder()`); the waiting order comes in when it closes.
- `aria-hidden`, never focused, keys never prevented; the column window never activated.
- Data: the page calls `api().peek(id)` when it opens and again on every `app.update()` while open (content redrawn only when it changed); with the column open, also `api().column(id, top)`, which reads `peek()` again (cached) and refills and places the window; `api().column_off()` hides it. `Panel.peek(sid)` returns `{id, prompt, bg: [{kind, what, text, since ms}]}`, or `None` for an unknown session; a closed session gets its prompt only. Nothing is kept by the pages, written or logged.
- Readers (only for the opened card; caches in `Panel.peeks` by transcript path):
  - `last_prompt()`: the last line of the transcript that `typed_prompt()` accepts (a `user` line that is not meta, sidechain, a tool result, a tag such as `<task-notification>` or `<command-name>`, a compaction summary or an interruption), searched in the last `PEEK_TAIL` 256 KB, then `PEEK_MORE` 4 MB; cached by (size, mtime).
  - `agent_prompt()` for a subagent: `follow_up()` (the latest SendMessage), else `first_prompt()`.
  - `follow_up()`: SendMessage writes into the agent's own `.jsonl`, in one of two forms, both with `origin` `{"kind": "coordinator"}`: a meta `user` line *The coordinator sent a message while you were working:* + the message (that first line dropped, `TOLD`), or an `attachment` line of type `queued_command` holding it in `prompt` (origin inside the attachment). Read on from where the last call stopped (the first call reads the last `PEEK_MORE`), only lines holding `"coordinator"` parsed; a line still being written waits for the next call.
  - `first_prompt()`: the first user line of a subagent's `.jsonl` or of a `claude -p` run's own transcript (`projects/<slug(cwd)>/<sid>.jsonl`), read from the first `PEEK_HEAD` 256 KB, its frame taken off by `unframe()`, cached for good once found. A Workflow tool agent's first line is a frame line starting `[Workflow harness — computed task]` ending *The computed task text follows:*, then the script's task with every line indented by two spaces (the harness says a column-zero line inside it would be forged): the indented lines are the task. A fork's file starts with a `fork-context-ref` line and the history it inherited (an older format repeats the parent's prompts as user lines); its task is the user line holding `<fork-boilerplate>…</fork-boilerplate>`, after *Your directive:* (`<` may be stored as `\u003c`, so the file is matched on `/fork-boilerplate`). A run without a transcript (`--no-session-persistence`) falls back to its command line (`command_line()`: `NtQueryInformationProcess` class 60 + `CommandLineToArgvW`; `print_prompt()`: the argument after `-p`/`--print`, else the longest non-option); a prompt given on stdin shows none.
  - `bg_commands()`: in the last `BG_TAIL` 4 MB, a `tool_use` with `run_in_background` (not Agent/Task) whose `tool_result` says `running in background with ID: X` at or after the process start, without a later `<task-id>X</task-id>` or a `TaskStop`/`KillShell` of X; cached by (size, mtime, start). Shown only when `late_child()` finds a child of the session's process born over `LATE` 20 s after it started. Same rule as `busy_work()` in `glm-fallback.py`.
  - `flat()`: whitespace collapsed, BOM removed, cut at `PEEK_CHARS` 1200 with `…`.
- Cost measured on a real 4 MB-tail session: first `peek()` 48 ms, cached 0.9 ms.
