# claude-plus-fa: reply to passages and the reply window

What is true now; history in [`trials.md`](../trials.md). Limits of these features stay in `memory.md` § Limits. Moved here whole from `memory.md` § Reply to a passage (2026-11-23), when the reply window was added.

## Reply to a passage
- Flow: select in Windows Terminal (`copyOnSelect` fills the clipboard), type `: my answer` or `:1 yes :3 no`, Enter; `quote-reply.py` adds the passages to the turn. The prompt itself is never changed.
- Markers: bare `:` at the start (`BARE`: not followed by a digit) and `:N` (`MARK`: `(?<!\S):(\d+)(?!\S)`). Not a marker (text the user quotes): a `:N` inside inline code or a fenced block (`code_spans()`, CommonMark-style); inside quotation marks on one line (`QUOTED`: `"…"`, curly, guillemets); inside a passage pasted from the conversation (`echoed()`: the `:N` and at least `ECHO` 16 characters next to it, on either side or both, stand word for word in a listed passage or in one of Claude's latest replies, both through `norm()`: backticks and `*` left out, whitespace runs as one space). Claude's replies: `said(transcript_path)`, the last `SAID_MAX` 40 main-thread text blocks of the transcript's last `SAID_TAIL` 512 KB, read only when the prompt holds a `:N`.
- With the panel's live list (`listed(session_id)`: the file says `on` and the mutex it names exists; only the hook's own session's list; none without `session_id`) the clipboard is never opened. `parse()` splits at listed markers; each answered passage goes as `<quote n="N"><passage>...</passage>[<note>cut</note>]<user_answer>...</user_answer></quote>`, after one sentence saying each `<user_answer>` is the user's own answer to its passage (`<user_answer>`, not `<reply>`, since 2026-11-23: a bare reply could read as the model's own); text before the first marker (the `My answers:` label of Send to Session) belongs to no answer; `systemMessage` `Quoted: :1 :3` (plus `(:5 matched nothing)`).
- Bare `:` with one listed passage: the single form (`single()`, `Quoted: <first 60 characters>…`); with several, all numbered without replies and a note that Claude may ask which is meant; empty list: `Reply: nothing to quote (no selection is listed)`. Only unlisted markers: `Reply: :N matched nothing`. Only quoted markers: the prompt goes untouched, nothing printed.
- Every prompt writes `reset_path(session_id)` when its session's list has entries, from which the panel empties that list.
- Without a live list a bare `:` quotes the clipboard (`from_clipboard()`): nothing when it holds no text, a private format (`ExcludeClipboardContentFromMonitorProcessing` present, or `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` 0 or unreadable), cannot be opened (20 tries 5 ms apart), or its sequence number equals the one in `USED`.
- Every passage is cut at `CAP` 4000 characters (`passage()`: CRLF as LF, stripped, cut, and how much was cut). Output is ASCII JSON; any error gives no output, exit 0.
- `write_json()` writes whole (`<path>.<pid>.tmp` + `os.replace`, retried 40 x 5 ms); `load()` retries `PermissionError` 5 x 2 ms.
- The panel loads this file (`load_quote()`: the repo copy beside the `.pyw`, else the installed hook) for `seq()`, `clip()`, `passage()`, `load()`, `write_json()`, `add()`, `apply_reset()`, `drop()`, `reset_path()` and the paths. Caps: `MAX_ITEMS` 50 per list, `MAX_LISTS` 20 lists.
- `LIST` = `{on, mutex, lists: {session_id: {gen, next, name, added, items}}}`, items `{n, seq, at, text, more}`; kept by the panel alone, written only on change; read back at start (`quote_load()`; the old machine-wide format is not read back). `quote_poll()` and Send to Session change it under `qlock`.
- `quote_poll()` on the 0.2 s turn: when `GetClipboardSequenceNumber` moved, one `clip(tries=1)`; not listed: no text, a private format, blank, the same as the last entry, or a clipboard with the paste mark. Returns True when the lists changed (the loop then calls `update_reply()`).
- Attribution (`copied_in()`, `tab_session()`): the clipboard owner's root window (Windows Terminal names the window of the selection); the copy joins the list of the one open, non-headless session whose `name` equals that window's `shown_name()` and whose console window (`window_of(pid)`, looked up afresh) is that window. No list when: no owner, not a session terminal, no listed name, two sessions with that name there, or the window's shown name changed since the previous turn while in front.
- Numbers never shift; numbering restarts at 1 under a new `gen` only when the list is empty. Reset: the panel stats each session's reset file every turn and, when its `gen` matches, drops entries up to `upto`; an emptied list is removed.
- Not live (strip or keeper off, panel hidden): every list empties and the file says `on: false`; when it comes back, the clipboard at that moment is not listed.
- The lists show in the reply window (marked in the reply, `:N` badge); the strip has no band of selections (since 2026-11-23), and no x that drops one selection.
- `copy_on_select.py`: `files()` = every Windows Terminal settings file that exists (Store stable/Preview/Canary under `%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal*_8wekyb3d8bbwe\LocalState`, unpackaged `%LOCALAPPDATA%\Microsoft\Windows Terminal`, Scoop `apps\windows-terminal*\current\settings`), deduplicated by real path. Edited as text: only the root member's value replaced, or `"copyOnSelect": true,` inserted after the root `{` (BOM, indent, line ending kept; written in place). Once per file, recorded in `copy-on-select.json`; a file already `true` recorded unchanged; backup `settings.json.before-claude-plus` once; an unparsable file skipped, not recorded. `restore()`: only records with `changed`, only while still `true`.

## The reply window: where and when
- `agent-reply.html` in a fifth pywebview window (`REPLY_TITLE` *Field Agents Reply*), hidden at start, frameless, `shadow=True` (DWM's frame: its own edged surface, apart from the strip's), `min_size=(0, 0)`, NOT `focus=False`: a click activates it so the user can type (`quiet_forms()` keeps it from taking the keyboard when made). `reply_up()` gives it `WS_EX_TOOLWINDOW` without `WS_EX_NOACTIVATE` and resets `head_key` so the next `update_strip()` sends the head; owned by the panel (`GWLP_HWNDPARENT`, set in `place_reply()` before the first show, then `wake()`), so it rises and sinks with the panel.
- One window for the tabs and the replies, the strip for the screenshots alone (2026-11-23): DWM edges each window, so the two read as two units with `SHOT_GAP` between them, and the reply window is as tall as its own content (no band beside a tall strip).
- Gate: shown while the strip switch is on, the keeper is on, the panel is shown and a session is open (a tab); also while the strip itself is hidden (no screenshot). Folded: `"reply_open": false` in `claude-plus.local.json` (`set_reply_open()`, the fold button; a tab press opens it again): the window shrinks to its head (`body.folded`).
- Place (`strip_rect()` → `band_layout(room, n, head)`, `place_reply()`): `room` = logical px from the strip's anchor (`strip_anchor()`: its top-right corner, saved or docked) to `SHOT_GAP` from the screen's left edge. The reply window: x = that left edge, y = the strip's top (the anchor's when no screenshot), width `REPLY_W` 820 (less only when the room minus the strip and `SHOT_GAP` is narrower); the strip keeps it `REPLY_MIN` (= `REPLY_W`) + `SHOT_GAP` and its screenshots wrap into rows first (at least one column; `cols` handed to `shotStrip.update(items, cols)`). Height = what the page reports (`natural()`: head, the limit question, the replies' own height plus `#body`'s padding (`#replies` is `flow-root`; not `#body.scrollHeight`, which never drops below the window's height, so the window would not shrink), the missing line, the bottom bar; `ReplyApi.size(h)`, event `reply`; `reply.head()` and `reply.show()` return it too), at least 40 px, up to `REPLY_BELOW` 8 px above the work area's bottom; past that its replies scroll inside (`#body`), the head and bottom bar stay.
- Drag: a press on the head (`ReplyApi.press/release` = the strip's `strip_press()`/`strip_release()`) moves both windows; `strip_follow()` moves the strip only while it is visible and saves `shot_strip_at` from the anchor, so the pair moves without screenshots too. A press released in place is a click (tab or fold).
- Head (`#head`, `reply.head(state)` from `head_state()` through `push_head()`, sent when it changed): a tab per open session (state dot as the panel's: red asking, turning green working, violet ring open; the name cut to 28 characters; the time of its last reply), the shown one outlined in blue; the fold button (chevron up: fold; down: open) at the right; the chip row of the shown session's pins (§ Pins) under the tabs, only while it has pins; 6 px under those `<name> · <folder> · last reply HH:MM, after your prompt of HH:MM` (or `working on your prompt of`, `no reply since your prompt of`); a hairline under the head (none when folded). Tabs and fold button 34 px. The head's buttons (tabs, fold, chips and their x) work by pointer alone and are out of the keyboard's order (`tabindex="-1"`), so Tab never lands on them. Tooltips (`data-tip`, under them): a tab's name and folder; *Folds the reply window to its tabs* / *Opens the reply window*. Head, replies, the bottom bar and its text share one left edge (`--edge` 20 px).
- Tabs (`reply_tabs()`): every open, non-headless session with a pid, except one Codex holds (`returns` via Codex with its window open); ordered by the later of `<sid>.prompt.json` `at` (`prompt-recall.py`) and the transcript's last typed prompt, newest first. Shown (`update_reply()`): the first tab (the session last typed in); a tab pressed (`ReplyApi.tab`, event `tab:<sid>`, `reply_pick`) holds until a prompt is typed in any tab after the press. A session's terminal coming to the front does the same as a tab press (`follow_terminal()`, below).
- Follow the terminal in front (`follow_terminal()`, every 0.2 s poll turn, on the `(foreground window, title)` the loop reads once a turn and also hands to `quote_poll(front)`; no hook or poll of its own): when `(window, shown_name(title))` differs from the previous turn's, `front_session()` names the session: none for the panel's own windows (`own()`: panel, strip, reply window), a window holding no listed open non-headless session, or a closed one; a window holding one session counts while its title matches `CLAUDE_TITLE`; one holding several through `tab_session()` (the tab in view shows the name; never a guess). That session, when it has a tab, becomes `reply_pick` (now), so a prompt typed later anywhere still switches as before. Nothing is focused or raised. Returning from the reply window to the same terminal counts as a change (the reply window was in front between).
- Updated on every live pass (2 s), scan, list change, tab press, terminal followed and pin change (event `reply-state`); `push_reply()` hands `reply.show(state)` only when the state's JSON changed.

## The reply window: content
- Replies (`agent-reply.py` `Transcript`, one per open transcript in `self.reads`, dropped when the session closes): the text blocks of every main-thread assistant message since the last typed prompt (`typed_prompt()`, the panel's own) whose `stop_reason` is `end_turn`, joined with a blank line; not `isSidechain`, `isApiErrorMessage`, model `<synthetic>`, thinking, tool calls or text in a message that ended in `tool_use`. A typed prompt empties the list. Lines are grouped by `message.id` (one line per content block, each carrying the message's `stop_reason`), deduplicated by `uuid`.
- Read on from the last whole line (`pos`); the first read takes the last `TAIL` 4 MB, then `MORE` 32 MB when no prompt is in it; a shorter file is read again from the start. A transcript is read only while its session is not `busy` (so the window changes when a turn ends), and once at first sight.
- Page (`reply.show({sid, name, replies: [{id, when, text}], answers, selections, note, pins})`): markdown blocks (`blocks()`): paragraphs (a single line break kept), headings (h1 17 px, h2 15 px, the rest 14 px, all semibold), list items (each its own paragraph, marker kept, nested by indent), quotes, tables, rules, fenced code shut as one 34 px line (chevron, language, `N lines`, first line), opened by a click. Table (GFM): a line with `|` followed by a dash row (`SEP`; `:-:`, `-:`, `:-` set the column's alignment), then every following non-blank line with `|`; outer pipes optional, `\|` stays in its cell (`cells()`); drawn as a `<table>` (1 px `--line` cells, tinted bold header row, tabular numbers, inline markdown in cells, missing cells empty), sideways scroll of its own when wider; lines starting with `|` without a dash row stay as written in monospace (`pre`). Inline: code, bold, italics, `~~strikethrough~~`, links (`[text](url)` and bare `http(s)://` addresses, trailing punctuation and quotation marks left out) drawn blue and underlined, the address as tooltip; a click opens it in the default browser (`ReplyApi.link`, `os.startfile`, only `http(s)://`). Several replies are parted by a hairline; each is led by its top line (its time, Pin at the right; § Pins). Empty: `note` ("Claude is working on your prompt of HH:MM. Its reply shows here when the turn ends." / "No reply since your prompt of HH:MM yet.").
- Answer box: a whole table is one paragraph (one box, its whole markdown the passage). Hover never opens a box: it tints the paragraph (`#replies .para:hover`) and, after the usual 400 ms, its tooltip says `Click to answer this paragraph` / `item` / `table` (`paraTip()`); none for a block whose box is open (`tipFor()`), and no paragraph hint at all while any answer box has the keyboard (`tipShow()` checks `typing()`; a box taking the keyboard hides one already showing). A click on the paragraph opens `Type your answer, or hold Space to speak…` under it with the caret in it; another click closes it while it is empty; a box holding text never closes on a click (the click focuses it), and once emptied the next click closes it. The rule is `clickAction()` (pure, run in node by `test-reply.py`): nothing on a drag (pointer moved `>=` 4 px from the press), with text selected after the click, on a double click's second click (`detail > 1`; its first click already opened the box), or on a link, a code block, Pin or a `:N` badge (those keep their own action). Several boxes can be open; the open empty ones (`opened`) and every box with an answer (drafts included) are open again after a redraw; a new session empties `opened`. The user's text in `--blue` on `#f5f8ff` with a 2 px blue left rule; auto-growing, never an inner scroll. Keys in a box (the page's capture-phase `keydown`, `stopPropagation`, so no other handler sees them; none while an IME composes): Enter keeps the text and leaves the box (`blur()`, the focus goes to no control; the draft is saved as after any typing); Tab and Shift+Tab (`tabMove()`, the index from `tabTarget()`, pure, run in node by `test-reply.py`) keep the text and open the next / previous block's box (every `#replies .para`: paragraph, heading, list item, quote, table, in reading order across all replies shown; code blocks and rules are skipped) with the caret at its end, scrolled into view (`scrollIntoView` nearest); the box left closes when empty, so tabbing past blocks leaves no trail, and stays when it holds text; at the last block Tab, at the first Shift+Tab, only leaves the box (closing it when empty); so Tab never reaches a session tab, chip or button; Esc keeps the text and leaves the box as Enter does (an exception to `design-forms.md`'s Esc-puts-back rule: losing a typed answer is worse here); Shift+Enter a new line. An emptied answer goes.
- Drafts (`Drafts`, `~/.claude/state/agent-panel/reply-drafts.json`, `{sid: {"<message id>#<block>": {text, passage, at}}}`): the page calls `ReplyApi.draft(sid, key, passage, text)` 300 ms after typing stops, with the session, passage and text taken when the key was typed (not when the timer fires); every method runs under the store's lock (pywebview runs each page call on a thread of its own), and `save_json()` writes through a temp file named per process and thread; kept across folds, restarts and session switches until sent; answers older than the session's last typed prompt are dropped (`expire()`, every pass). The passage is the paragraph's markdown source.
- Selections: the session's numbered list, each passage marked where it stands (`mark()`: rendered text vs. passage with whitespace runs as one space, backticks, `*` and the terminal's box-drawing characters U+2500 to U+257F dropped, a leading `●⎿•` dropped, each table cell its own run of text; failing that, with no whitespace at all; a row selected from the terminal's drawn table is marked cell by cell) with a blue `:N` badge before it; those not found are listed in a line above the bottom bar ("Not in these replies: :2 …", first 60 characters).
- Bottom bar: `N answers · N more under another chip · N selections · draft kept` (the count is the answers under what is shown; Copy and Send to Session take exactly those: `sendList()`, pure, run in node by `test-reply.py`, from the page's `answers`, not from the boxes in the page, in the order their blocks stand) ("No answer yet" with none), the outcome line, **Copy**, **Send to Session** (both off with no answer). While an answer box has the keyboard nothing is redrawn and what the panel sends meanwhile is held whole (`reply.show()`: the state, `S` included; `reply.head()`: a head whose shown tab is another session) until the box is left (`flush()` on `focusout`; Tab to the next box keeps it held): the page stays the session drawn, so answers typed meanwhile are saved, counted and sent as that session's. Any other head (fold, dots, times) is drawn at once.

## Voice typing in an answer box (Space held)
- Windows' own dictation (Win+H) types into the box; the panel records nothing. Claude Code's own voice feature cannot be called from another program.
- The rule is `spaceRule()` (pure, run in node by `test-reply.py`): a plain Space keydown in a box (no modifier, not composing) is held back; key repeat never types. Space up before `HOLD` 400 ms types one space (`execCommand("insertText")`, so undo and `input` work); another key going down first puts the space in at once, before it (rolled-over typing). Held `HOLD` ms: `ReplyApi.voice(true)`; Space up, the box losing the keyboard or the window losing focus: `voice(false)`. Calls go one after another (`voiceQueue`); keys typed while listening go in as typed.
- The line under the box (`.vline`, `role="status"`): `Starting Windows voice typing…`; listening: a red dot, `Listening… release Space to stop.`, the box's rule and ring red (`.listening`); could not start: the note in amber (no dialog, nothing typed), kept until the next key in that box or the box loses the keyboard. The Settings page a note names is a link in it (`a.lnk` with `data-settings`, the reply links' blue underline, tooltip *Opens this page of Windows Settings*; the note's words in one `span` so the flex line wraps as text): a press on it is `preventDefault`ed on `mousedown`, so the box keeps the keyboard and the note stays; the click calls `ReplyApi.settings(uri)` → `open_settings()`, which opens only the URIs in `VOICE_LINKS` (`AllowSetForegroundWindow(ASFW_ANY)`, then `os.startfile`: the click made the reply window the foreground, so Settings comes up in front). The box is neither closed nor toggled; Settings taking the foreground then takes the note, as any loss of the keyboard does.
- `agent-reply.py` `Voice` (the panel's `self.voice`, its `front()` = the reply window is the foreground window): `start()` checks `voice_block()` first, then sends Win+H as one `SendInput` of four events (LWin extended) only while the reply window is in front, and waits up to `VOICE_WAIT` 1.5 s for the bar; `stop()` sends Win+H again only while the bar it opened still shows and the reply window is in front, so dictation that ended by itself is never started again. Both under one lock.
- The bar: Windows' dictation bar is a no-activate, topmost `ApplicationFrameWindow` of `explorer.exe` (888 x 55 at the screen's top centre at 100 %), cloaked while closed; `EnumWindows` does not list it, `FindWindowExW` does (`flyouts()`, own `WinDLL` instances so the panel's argtypes stay its own). Explorer keeps several such flyouts (the emoji panel's too), so the bar is the one that left its cloak after our Win+H. The reply window keeps the foreground and the box the keyboard while the bar shows.
- `voice_block()` notes, checked in this order: `HKLM\SOFTWARE\Policies\Microsoft\InputPersonalization` `AllowInputPersonalization` 0 (`VOICE_POLICY`); `HKCU\Software\Microsoft\Speech_OneCore\Settings\OnlineSpeechPrivacy` `HasAccepted` not 1 (`VOICE_OFF`: Windows 10 dictation runs only online; with it off Win+H opens the bar with only "To use dictation, go to Settings and turn on online speech recognition"); the microphone's `ConsentStore\microphone` `Value` `Deny` in HKLM or HKCU (`VOICE_MIC_DENIED`); `waveInGetNumDevs()` 0 (`VOICE_NO_MIC`). The bar not showing in time: `VOICE_NOT_STARTED`. `voice_note()` answers the note with its link from `VOICE_LINKS`: `VOICE_OFF` Settings › Privacy › Speech (`ms-settings:privacy-speech`), `VOICE_MIC_DENIED` Settings › Privacy › Microphone (`ms-settings:privacy-microphone`), `VOICE_NO_MIC` Settings › System › Sound (`ms-settings:sound`, where an input device is turned on); `VOICE_POLICY` and `VOICE_NOT_STARTED` have none (nothing there the user can change).
- Language: dictation takes the input language of the window (on this PC only en-US is installed, its Turkish Q layout included, so English); Windows reports an unsupported one in its own bar, which `stop()` closes.

## Copy and Send to Session
- Copy (`ReplyApi.copy` → `copy_text()` → `set_clipboard_text()`, plain `CF_UNICODETEXT`): the line `My answers: :1 … :2 …` numbered in the window's order, a blank line, then per answer `:N` and its passage with `> ` before each line.
- Send to Session (`reply_send()`, on the page's API thread): each answered passage joins the session's list (`add()`, `seq` None; the same passage as the last entry reuses its number), the list is written, `send_line()` builds `My answers: :N answer :N answer` (`LABEL`, so the prompt itself says these are the user's answers; `one_line()`: whitespace collapsed, lines joined with a space, a `:N` typed inside an answer wrapped in backticks so the hook never takes it for a marker); `focus_session()` brings the terminal forward (Ctrl+Tab through tabs as a card click does); up to `SEND_FRONT` 1.5 s (`bring_front()` once more at half time) until `front_state()` (pure, tested) passes: the foreground window, AND the top ordinary window (`top_window()`: nothing covers it), with a Claude Code title (`CLAUDE_TITLE`), showing this session's tab when the window is shared; else the note names what is missing (`it is not the window in front`, `another window covers it`, `it shows no Claude Code tab`, `another tab is showing`); then `SEND_SETTLE` 0.25 s (the terminal's own focus report reaches Claude Code apart from the pasted line); then `WM_COPYDATA` (`dwData` `TYPE_TEXT`, JSON `{id, hwnd, text}`) to the paste key's window, and `WM_TYPED` (0x8002, wParam id) polled up to `SEND_WAIT` 4 s. Read: if anything came over the terminal meanwhile it is raised again; the sent answers' drafts cleared (`drafts.clear(sid, keys)`; those under another chip stay), "Typed into <name> as :2 :3. Press Enter there to send it." Any failure removes the entries it added and says why, ending "Use Copy."
- Every Send to Session is logged, one line per step and no text, to `~/.claude/state/agent-panel/reply-send.log` (`send_log()`, cut to 32 KB past 64 KB): `send <sid 8> answers N characters N`, `front ok|<what is missing> <s>`, `paste key <why>`, `typed read|not read`, `after <what> raised again: ok|<what>`.
- The paste key's side (`agent-panel-paste.py` `request()`, `type_text()`): accepted only when not busy, the target is the foreground window and a listed session window with a Claude Code title (answers 1 started, 2 busy, 3 not in front, 4 not Claude, 5 bad request); then exactly the picture path's machinery: `save_clip()`, the text as delayed-render `CF_UNICODETEXT` with the mark and quiet formats, Ctrl+V sent, rendered only to the terminal's process, the clipboard restored. Enter is never pressed. Logged `type read, restored N characters`.

## Pins
- Pin (`.rpin`, the strip's Pin look: 20 px, `--r-small`, blue filled when on) at the right of every reply's top line (`.rtop`: its time, now shown for a single reply too); tooltips *Keeps this reply as a chip under the tabs, after newer prompts and restarts* / *Unpins this reply: its chip under the tabs goes*. A click calls `ReplyApi.pin(sid, id, text, mode)` (`pin`, `unpin`, `swap`) → `reply_pin()`, which takes the reply's text and time from the transcript (the page's copy when the transcript no longer holds it) and answers `{pins}` or `{full, pins}`.
- Store (`agent-reply.py` `Pins`, `~/.claude/state/agent-panel/reply-pins.json`, `{sid: [{id, at, text, pinned}]}` in pin order, a lock for the API thread): the reply's own text, so a pin stays through newer prompts, compaction and a transcript read again; per session id, kept after the session closes and shown again with its tab; `PIN_MAX` 8 per session (`add()` answers `added`, `already`, `full` without a change, `empty`); `swap()` drops the oldest pin and adds; read back clean at start (bad entries dropped, the last 8 kept). Deleted with the state folder by `uninstall.py`.
- Chip row (`#chips` in the head, `drawChips()`, only while the shown session has pins; 28 px chips, `--r-ctl`, the shown one outlined as a tab): **Latest** first (*Shows the replies since your last prompt*), then a chip per pin in pin order: pin glyph, `pin_label()` (the first 5 words of the first line with text, markdown's marks dropped, cut at 32 characters, `…` when cut), the reply's time (`HH:MM`, `DD Mon HH:MM` when not today; `pins_of()`), and an x (*Unpins this reply. Its chip and the text kept with it go*). Chips wrap into more rows.
- A chip shows its pinned reply in place of the latest ones (`view`, page-side; `shownReplies()`), with the same answer boxes (draft keys are the message id, so an answer typed there is a draft as any), selections marked in it, Copy and Send to Session. Back to the latest: **Latest**, a press on the shown session's tab, or another session shown (a tab, a typed prompt, a terminal followed); following the terminal of the session already shown keeps the chip. Unpinning the pin shown goes back to Latest. A press on the head leaves a focused answer box first, so the chip or tab press redraws at once.
- Limit: Pin on a 9th reply shows `#ask` under the head (amber line, no dialog): "A session keeps 8 pins at most. Unpin the oldest, “<words>” (<time>), and pin this one?" with **Unpin Oldest and Pin** (`swap`) and **Cancel**; it goes with Cancel, a pin change or another session.
