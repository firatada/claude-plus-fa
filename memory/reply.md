# claude-plus-fa: reply to passages and the reply window

What is true now; history in [`trials.md`](../trials.md). Limits of these features stay in `memory.md` § Limits. Moved here whole from `memory.md` § Reply to a passage (2026-11-23), when the reply window was added.

## Reply to a passage
- Flow: select in Windows Terminal (`copyOnSelect` fills the clipboard), type `: my answer` or `:1 yes :3 no`, Enter; `quote-reply.py` adds the passages to the turn. The prompt itself is never changed.
- Markers: bare `:` at the start (`BARE`: not followed by a digit) and `:N` (`MARK`: `(?<!\S):(\d+)(?!\S)`). Not a marker (text the user quotes): a `:N` inside inline code or a fenced block (`code_spans()`, CommonMark-style); inside quotation marks on one line (`QUOTED`: `"…"`, curly, guillemets); inside a passage pasted from the conversation (`echoed()`: the `:N` and at least `ECHO` 16 characters next to it, on either side or both, stand word for word in a listed passage or in one of Claude's latest replies, both through `norm()`: backticks and `*` left out, whitespace runs as one space). Claude's replies: `said(transcript_path)`, the last `SAID_MAX` 40 main-thread text blocks of the transcript's last `SAID_TAIL` 512 KB, read only when the prompt holds a `:N`.
- With the panel's live list (`listed(session_id)`: the file says `on` and the mutex it names exists; only the hook's own session's list; none without `session_id`) the clipboard is never opened. `parse()` splits at listed markers; each answered passage goes as `<quote n="N"><passage>...</passage>[<note>cut</note>]<user_answer>...</user_answer></quote>`, after one sentence saying each `<user_answer>` is the user's own answer to its passage (`<user_answer>`, not `<reply>`, since 2026-11-23: a bare reply could read as the model's own); text before the first marker belongs to no answer; `systemMessage` `Quoted: :1 :3` (plus `(:5 matched nothing)`).
- Bare `:` with one listed passage: the single form (`single()`, `Quoted: <first 60 characters>…`); with several, all numbered without replies and a note that Claude may ask which is meant; empty list: `Reply: nothing to quote (no selection is listed)`. Only unlisted markers: `Reply: :N matched nothing`. Only quoted markers: the prompt goes untouched, nothing printed.
- Every prompt writes `reset_path(session_id)` when its session's list has entries, from which the panel empties that list.
- Without a live list a bare `:` quotes the clipboard (`from_clipboard()`): nothing when it holds no text, a private format (`ExcludeClipboardContentFromMonitorProcessing` present, or `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` 0 or unreadable), cannot be opened (20 tries 5 ms apart), or its sequence number equals the one in `USED`.
- Every passage is cut at `CAP` 4000 characters (`passage()`: CRLF as LF, stripped, cut, and how much was cut). Output is ASCII JSON; any error gives no output, exit 0.
- `write_json()` writes whole (`<path>.<pid>.tmp` + `os.replace`, retried 40 x 5 ms); `load()` retries `PermissionError` 5 x 2 ms.
- The panel loads this file (`load_quote()`: the repo copy beside the `.pyw`, else the installed hook) for `seq()`, `clip()`, `passage()`, `load()`, `write_json()`, `add()`, `apply_reset()`, `drop()`, `reset_path()` and the paths. Caps: `MAX_ITEMS` 50 per list, `MAX_LISTS` 20 lists.
- `LIST` = `{on, mutex, lists: {session_id: {gen, next, name, added, items}}}`, items `{n, seq, at, text, more}`; kept by the panel alone, written only on change; read back at start (`quote_load()`; the old machine-wide format is not read back). `quote_poll()` changes it under `qlock`.
- `quote_poll()` on the 0.2 s turn: when `GetClipboardSequenceNumber` moved, one `clip(tries=1)`; not listed: no text, a private format, blank, the same as the last entry, or a clipboard with the paste mark. Returns True when the lists changed (the loop then calls `update_reply()`).
- Attribution (`copied_in()`, `tab_session()`): the clipboard owner's root window (Windows Terminal names the window of the selection); the copy joins the list of the one open, non-headless session whose `name` equals that window's `shown_name()` and whose console window (`window_of(pid)`, looked up afresh) is that window. No list when: no owner, not a session terminal, no listed name, two sessions with that name there, or the window's shown name changed since the previous turn while in front.
- Numbers never shift; numbering restarts at 1 under a new `gen` only when the list is empty. Reset: the panel stats each session's reset file every turn and, when its `gen` matches, drops entries up to `upto`; an emptied list is removed.
- Not live (strip or keeper off, panel hidden): every list empties and the file says `on: false`; when it comes back, the clipboard at that moment is not listed.
- The lists show in the reply window (marked in the reply, `:N` badge); the strip has no band of selections (since 2026-11-23), and no x that drops one selection.
- `copy_on_select.py`: `files()` = every Windows Terminal settings file that exists (Store stable/Preview/Canary under `%LOCALAPPDATA%\Packages\Microsoft.WindowsTerminal*_8wekyb3d8bbwe\LocalState`, unpackaged `%LOCALAPPDATA%\Microsoft\Windows Terminal`, Scoop `apps\windows-terminal*\current\settings`), deduplicated by real path. Edited as text: only the root member's value replaced, or `"copyOnSelect": true,` inserted after the root `{` (BOM, indent, line ending kept; written in place). Once per file, recorded in `copy-on-select.json`; a file already `true` recorded unchanged; backup `settings.json.before-claude-plus` once; an unparsable file skipped, not recorded. `restore()`: only records with `changed`, only while still `true`.

## The reply window: where and when
- `agent-reply.html` in a fifth pywebview window (`REPLY_TITLE` *Field Agents Reply*), hidden at start, frameless, `shadow=True` (DWM's frame: its own edged surface, apart from the strip's), `min_size=(0, 0)`, NOT `focus=False`: a click activates it so the user can type (`quiet_forms()` keeps it from taking the keyboard when made). `reply_up()` gives it `WS_EX_TOOLWINDOW` without `WS_EX_NOACTIVATE` and resets `head_key` so the next `update_strip()` sends the head; owned by the panel (`GWLP_HWNDPARENT`, set in `place_reply()` before the first show, then `wake()`), so it rises and sinks with the panel.
- One window for the tabs and the replies, the strip for the screenshots alone (2026-11-23): DWM edges each window, so the two read as two units with `SHOT_GAP` between them, and the reply window is as tall as its own content (no band beside a tall strip).
- Gate: shown while the strip switch is on, the keeper is on, the panel is shown and a session is open (a tab); also while the strip itself is hidden (no screenshot). Folded: `"reply_open": false` in `claude-plus.local.json` (`set_reply_open()`, the fold button; a tab press opens it again): the window shrinks to its head (`body.folded`).
- Place (`strip_rect()` → `band_layout(room, n, head)`, `place_reply()`): `room` = logical px from the strip's anchor (`strip_anchor()`: its top-right corner, saved or docked) to `SHOT_GAP` from the screen's left edge. The reply window: x = that left edge, y = the strip's top (the anchor's when no screenshot); with screenshots it and a full row of the strip share one width `w` = `REPLY_W` 820, or half the room less `SHOT_GAP` when narrower (since 2026-11-24, so their edges match; the screenshots wrap into rows, `cols` handed to `shotStrip.update(items, cols)`); without screenshots `REPLY_W` (less only when the room is narrower); when `w` holds under two columns the strip takes one and the reply window `REPLY_MIN` (= `REPLY_W`) or the rest. Height = what the page reports (`natural()`: head, the limit question, the replies' own height plus `#body`'s padding (`#replies` is `flow-root`; not `#body.scrollHeight`, which never drops below the window's height, so the window would not shrink), the missing line, the bottom bar; `ReplyApi.size(h, head)` with the head's own height too (one row of the strip matches it: [`screenshots.md`](./screenshots.md) § Layout), event `reply`; `reply.head()` and `reply.show()` return it too), at least 40 px, up to `REPLY_BELOW` 8 px above the work area's bottom; past that its replies scroll inside (`#body`), the head and bottom bar stay.
- Drag: a press on the head (`ReplyApi.press/release` = the strip's `strip_press()`/`strip_release()`) moves both windows; `strip_follow()` moves the strip only while it is visible and saves `shot_strip_at` from the anchor, so the pair moves without screenshots too. A press released in place is a click (tab or fold).
- Head (`#head`, `reply.head(state)` from `head_state()` through `push_head()`, sent when it changed): a tab per open session (its whole name, `head_state()` sends it uncut; under it the state dot as the panel's: red asking, turning green working, violet ring open, and the time of its last reply in 9 px muted type), the shown one outlined in blue; the fold button (chevron up: fold; down: open) at the right; the chip row of the shown session's pins (§ Pins) under the tabs, only while it has pins; 6 px under those `<name> · <folder> · last reply HH:MM, after your prompt of HH:MM` (or `working on your prompt of`, `no reply since your prompt of`), the folder (`where_of()`) a link (§ Links), the name plain text (no target of its own: the tab already shows the session); a hairline under the head (none when folded). Tabs and fold button `--tabh` 46 px (`min-height`). Tab layout (`tabFit()`, on every head drawn and on every width change through a `ResizeObserver`): a grid of equal columns `TAB_MIN` 72 to `TAB_MAX` 168 px wide (nine tabs in one row at 808 px), more rows when more tabs than fit, never a tab out of sight; the name (`nameFit()`, 13 px lines): for each size of `NAME_SIZES` 12, 11, 10 px, one line or two broken only at spaces and `_ - . / \` (`<wbr>`), then two lines broken anywhere, else two lines at 10 px ending in `…` (whole name in the tooltip). The head's buttons (tabs, fold, chips and their x) work by pointer alone and are out of the keyboard's order (`tabindex="-1"`), so Tab never lands on them. Tooltips (`data-tip`, under them): a tab's name and folder; *Folds the reply window to its tabs* / *Opens the reply window*. Head, replies, the bottom bar and its text share one left edge (`--edge` 20 px).
- Tabs (`reply_tabs()`): every open, non-headless session with a pid, except one Codex holds (`returns` via Codex with its window open); ordered by the later of `<sid>.prompt.json` `at` (`prompt-recall.py`) and the transcript's last typed prompt, newest first. Shown (`update_reply()`): the first tab (the session last typed in); a tab pressed (`ReplyApi.tab`, event `tab:<sid>`, `reply_pick`) holds until a prompt is typed in any tab after the press. A session's terminal coming to the front does the same as a tab press (`follow_terminal()`, below).
- Follow the terminal in front (`follow_terminal()`, every 0.2 s poll turn, on the `(foreground window, title)` the loop reads once a turn and also hands to `quote_poll(front)`; no hook or poll of its own): when `(window, shown_name(title))` differs from the previous turn's, `front_session()` names the session: none for the panel's own windows (`own()`: panel, strip, reply window), a window holding no listed open non-headless session, or a closed one; a window holding one session counts while its title matches `CLAUDE_TITLE`; one holding several through `tab_session()` (the tab in view shows the name; never a guess). That session, when it has a tab, becomes `reply_pick` (now), so a prompt typed later anywhere still switches as before. Nothing is focused or raised. Returning from the reply window to the same terminal counts as a change (the reply window was in front between). An answer box (with a draft or empty) does not keep the tab once the terminal is in front (§ Bottom bar's hold).
- Updated on every live pass (2 s), scan, list change, tab press, terminal followed and pin change (event `reply-state`); `push_reply()` hands `reply.show(state)` only when the state's JSON changed.

## The reply window: content
- Replies (`agent-reply.py` `Transcript`, one per open transcript in `self.reads`, dropped when the session closes): the text blocks of every main-thread assistant message since the last typed prompt (`typed_prompt()`, the panel's own) whose `stop_reason` is `end_turn`, joined with a blank line; not `isSidechain`, `isApiErrorMessage`, model `<synthetic>`, thinking, tool calls or text in a message that ended in `tool_use`. A typed prompt empties the list. Lines are grouped by `message.id` (one line per content block, each carrying the message's `stop_reason`), deduplicated by `uuid`.
- Read on from the last whole line (`pos`); the first read takes the last `TAIL` 4 MB, then `MORE` 32 MB when no prompt is in it; a shorter file is read again from the start. A transcript is read only while its session is not `busy` (so the window changes when a turn ends), and once at first sight.
- Page (`reply.show({sid, name, replies: [{id, when, text}], answers, selections, note, pins})`): markdown blocks (`blocks()`): paragraphs (a single line break kept), headings (h1 17 px, h2 15 px, the rest 14 px, all semibold), list items (each its own paragraph, marker kept, nested by indent), quotes, tables, rules, fenced code drawn open, under a 34 px head (chevron, language, `N lines`), whatever its length (asked 2026-11-25: shut blocks hid what the reply showed); a click on the head shuts it to that line with its first line beside it, another opens it; the choice is not kept, a redraw opens it again. Table (GFM): a line with `|` followed by a dash row (`SEP`; `:-:`, `-:`, `:-` set the column's alignment), then every following non-blank line with `|`; outer pipes optional, `\|` stays in its cell (`cells()`); drawn as a `<table>` (1 px `--line` cells, tinted bold header row, tabular numbers, inline markdown in cells, missing cells empty), sideways scroll of its own when wider; lines starting with `|` without a dash row stay as written in monospace (`pre`). Inline: code, bold, italics, `~~strikethrough~~`, links (`[text](url)` showing its text, and bare `http(s)://` and `file://` addresses, trailing punctuation and quotation marks left out) drawn blue and underlined, the address as tooltip (§ Links). Several replies are parted by a hairline; each is led by its top line (its time, Pin at the right; § Pins). Empty: `note` ("Claude is working on your prompt of HH:MM. Its reply shows here when the turn ends." / "No reply since your prompt of HH:MM yet.").
- Answer box: a whole table is one paragraph (one box, its whole markdown the passage). Hover never opens a box: it tints the paragraph (`#replies .para:hover`) and, after the usual 400 ms, its tooltip says `Click to answer this paragraph` / `item` / `table` (`paraTip()`); none for a block whose box is open (`tipFor()`), and no paragraph hint at all while any answer box has the keyboard (`tipShow()` checks `typing()`; a box taking the keyboard hides one already showing). A click on the paragraph opens `Type your answer, or hold Space to speak…` under it with the caret in it; another click closes it while it is empty; a box holding text never closes on a click (the click focuses it), and once emptied the next click closes it. The rule is `clickAction()` (pure, run in node by `test-reply.py`): nothing on a drag (pointer moved `>=` 4 px from the press; it draws the area, § The area), on a double or triple click's later clicks (`detail > 1`; its first click already opened the box), or on a link (any `a.lnk`, and its `.lnote`), a code block, Pin or a `:N` badge (those keep their own action). A click counts on what was pressed (`clickTarget()`): when the press made the page move under a still pointer (an empty box above it closed) and the click lands on what holds both, the pressed paragraph or link still acts. Several boxes can be open; the open empty ones (`opened`) and every box with an answer (drafts included) are open again after a redraw; a new session empties `opened`. The user's text in `--blue` on `#f5f8ff` with a 2 px blue left rule; auto-growing, never an inner scroll. Keys in a box (the page's capture-phase `keydown`, `stopPropagation`, so no other handler sees them; none while an IME composes): Enter keeps the text and leaves the box (`blur()`, the focus goes to no control; the draft is saved as after any typing); Tab and Shift+Tab (`tabMove()`, the index from `tabTarget()`, pure, run in node by `test-reply.py`) keep the text and open the next / previous block's box (every `#replies .para`: paragraph, heading, list item, quote, table, in reading order across all replies shown; code blocks and rules are skipped) with the caret at its end, scrolled into view (`scrollIntoView` nearest); the box left closes when empty, so tabbing past blocks leaves no trail, and stays when it holds text; at the last block Tab, at the first Shift+Tab, only leaves the box (closing it when empty); so Tab never reaches a session tab, chip or button; Esc keeps the text and leaves the box as Enter does (an exception to `design-forms.md`'s Esc-puts-back rule: losing a typed answer is worse here); Shift+Enter a new line. An emptied answer goes.
- Quick answers (asked 2026-11-25: "hızlıca onaylıyorum yazabileceğimiz bir etiket"): every answer box, paragraph's and area's (`boxHtml()`), holds a `.quick` row of chips after its textarea, one per text of the state's `quick` (`quick_answers()` in `agent-panel.pyw`: `"quick_answers"` in `claude-plus.local.json`, a list kept in order with blank and non-text entries left out, `[]` for none; anything but a list gives `QUICK_ANSWERS` `["I approve"]`, English because the package is public; read on every `push_reply()`, so an edit shows within a pass). Shown only while the box is empty (`:placeholder-shown`; also hidden while Space dictates, `.listening`/`.ghosted`): a shortcut for the common one-word answer that gets out of the way once anything is typed, and comes back when the box is emptied. Look: Pin's (20 px, `--r-small`, `--line` border, muted 600 11 px, blue on hover), 7 px from the box's top, 6 px from its right, 4 px apart, so side by side they share one height; the box's right padding becomes `--qw` (the row's width + 12 px, `quickFit()`: when a box is made, when one is emptied, when the window unfolds; never from a hidden row, which measures 0) while they show, so the placeholder and caret never run under them (a narrow box wraps the placeholder and grows). Tooltip *Puts this text in the box*; `tabindex="-1"`, so Tab still goes box to box. A press: `mousedown` `preventDefault`ed (capture), so the box keeps the keyboard (an empty box left would close on `focusout` before the click); the click (`quickPut()`, handled before `.ansrow`'s and the paragraph's, so never `clickAction()`; `areaPress()` already counts it a control) focuses the box when it was not, then `execCommand("insertText")` (Ctrl+Z undoes it; its `input` event saves the draft as typing does), else `quickInsert()` (pure, node-tested) at the caret; the caret stays after the text, the box is not left, so it neither closes nor redraws. A new list (`quickSync()` in `apply()`) re-renders the chips of every box open, once updates are no longer held.
- Drafts (`Drafts`, `~/.claude/state/agent-panel/reply-drafts.json`, `{sid: {"<message id>#<block>": {text, passage, at}}}`): the page calls `ReplyApi.draft(sid, key, passage, text)` 300 ms after typing stops, with the session, passage and text taken when the key was typed (not when the timer fires); every method runs under the store's lock (pywebview runs each page call on a thread of its own), and `save_json()` writes through a temp file named per process and thread; kept across folds, restarts, session switches and sends; answers older than the session's last typed prompt are dropped (`expire()`, every pass). The passage is the paragraph's markdown source.
- Selections: the session's numbered list, each passage marked where it stands (`mark()`: rendered text vs. passage with whitespace runs as one space, backticks, `*` and the terminal's box-drawing characters U+2500 to U+257F dropped, a leading `●⎿•` dropped, each table cell its own run of text; failing that, with no whitespace at all; a row selected from the terminal's drawn table is marked cell by cell) with a blue `:N` badge before it; those not found are listed in a line above the bottom bar ("Not in these replies: :2 …", first 60 characters).
- Bottom bar: `N answers · sent · N more under another chip · N selections` (the count is the answers under what is shown; Copy and Send to Session take exactly those: `sendList()`, pure, run in node by `test-reply.py`, from the page's `answers`, not from the boxes in the page, in the order their blocks stand) ("No answer yet" with none; `sent` while what the buttons would take is what this session's last Send to Session pasted, `sentAs`, this run only, so an answer changed since drops it), the outcome line, **Copy**, **Send to Session**, never off (asked 2026-11-25; before, both were off with no answer): with no answer they take each reply shown as it is (`toSend()`: a key `<message id>#` with no text; tooltips say which). The page has no Clear: an answer goes when its box is emptied or a newer prompt is typed (`Drafts.expire()`). While an answer box has the keyboard of the window in front (`holdsUpdates()`, pure, run in node by `test-reply.py`: the box is `document.activeElement` and `document.hasFocus()`), or a hold's words are still being transcribed (`rec`, `busy`), nothing is redrawn and what the panel sends meanwhile is held whole (`reply.show()`: the state, `S` included; `reply.head()`: a head whose shown tab is another session) until that ends (`release()` → `flush()` on `focusout`, on the window's `blur` and when dictation finishes; Tab to the next box keeps it held): the page stays the session drawn, so answers typed meanwhile are saved, counted and sent as that session's. Another window in front ends the hold although the box keeps the focus (it did not before 2026-11-25, so the tab stayed on the session typed in while another terminal was in front); the box's text is that session's draft, back when it is shown again. Any other head (fold, dots, times) is drawn at once.

## Links
- Why the reply window opens them: Claude Code wraps lines itself and writes OSC 8 hyperlinks only for http(s) (checked in 2.1.331); a markdown link to a file is printed as `text (url)`, and Windows Terminal's own URL detection does not join hard-wrapped lines, so Ctrl+click opens only half of a long `file:///` link.
- Drawn by `inline()`: a markdown link (its text shown), a bare `http(s)://` or `file://` address. A Windows path (`C:\` or `C:/`) in plain text (a run without spaces) or as a whole inline code (`WPATH`, spaces allowed) is a candidate (`span.cand`); after each `draw()`, `linkPaths()` asks `ReplyApi.paths` → `existing_paths()` (`os.path.exists`, at most `PATHS_MAX` 200 a call) and turns those found into links, the rest back into plain text (answers kept per page: found for its life, not found for `PATH_RECHECK` 10 s). Same in paragraphs, list items, tables, quotes, headings and a pinned reply (all go through `inline()`). Copy and Send to Session take the stored reply text, so the pasted link stays the original markdown.
- A click (`ReplyApi.link` → `agent-reply.py` `open_link()`, after `AllowSetForegroundWindow(ASFW_ANY)`; no `href`, `preventDefault`, never navigated in the WebView): `http(s)://` → `os.startfile` (the default browser); else `link_path()` (a `file://` URL with its escapes decoded: `file:///C:/…`, `file://localhost/…`, `file://host/share/…` as UNC; or a Windows path as written, slashes turned). Missing: note `LINK_MISSING` "File not found". A file with an extension in `RUN_EXT` (programs, scripts, shortcuts, `.reg`, `.py`) is shown selected in File Explorer (`explorer /select,`), never run. Anything else: `os.startfile` (Windows' handler for that file or folder). Not a web or file link: "Only web and file links open here"; `OSError`: "Could not open this".
- The folder in the head's line (`#meta a.lnk`, tooltip *Opens this folder in File Explorer*): the head takes the press (its drag), so it opens on a press released in place (`pointerup`, `openLink()`, as a reply's link), never on the click; it shows no tab, folds nothing, opens no answer box and leaves the keyboard where it was. A folder gone since: the same note.
- The note: one `.lnote` in the whole page (amber, 12 px, `role=status`) right after the link, gone after `LINK_NOTE_MS` 4 s or at the next link click; `mark()` skips it, a click on it opens no box.

## Copy and Send to Session
- Copy (`ReplyApi.copy` → `reply_text()` → `set_clipboard_text()`, plain `CF_UNICODETEXT`; it answers the clipboard's sequence number after the write, False when busy): the same text Send to Session pastes.
- Send to Session and Copy use `reply_text()` and `format_answered_replies()` to assemble each answered reply in full from its message id under `HEAD` `My answers inside your reply of HH:MM (your reply is quoted with "> ", my answers start with "My answer"):`, with the user's text right after its block, led by `ANSWER` `My answer to "<the block's first line>":` (`lead()`: the first non-blank line of the passage, cut at `NAME_CUT` 60 with `…`, `"` as `'`, a `:N` in backticks; `ANSWER_BARE` `My answer:` only for a passage with no text; asked 2026-11-25: a bare `My answer:` could read as an answer to the whole section; an area's answer: § The area); a reply sent with no answer (`answer_block(text, when, [])`) is quoted whole under `PLAIN` `Your reply of HH:MM, quoted with "> ":`. This preserves context when answering an older pinned reply. The paste does not add numbered selections.
- Send to Session brings the matching terminal tab to the front and checks foreground, stacking order and tab title. It asks the paste key process to paste the block at the cursor without Enter, after what the prompt holds. Claude Code can show a collapsed multiline paste. The answers stay in their boxes and drafts after a send, as after a failure (asked 2026-11-25: until then a paste acknowledged cleared them, so a `[Pasted text #N +M lines]` deleted by mistake in the terminal lost them); each press pastes the whole block again, one more copy, and the user deletes extras there. A press while one is on its way does nothing (`sending`). On failure the note offers Copy. Outcome: "Pasted into <name>: N answers inside the reply…", with no answer "Pasted the reply into <name>…"; no reply shown (Claude still working): "There is no reply here yet.", nothing pasted.
- `reply-send.log` records the focus and paste steps and the answer, character and line counts without draft text.

## The area (copy part of the replies, or answer it as a whole)
- Asked 2026-11-25 ("no button: I click with the mouse and select the area"), then "Her yerden başlayabilsin çerçeve": no button turns it on, and a drag starting anywhere in the replies draws it, on text and links too; it replaced the browser's drag selection there. `areaPress()` (pure, node-tested): their own for another button than the left, a control (`button, textarea, .ansrow`: the code block's head, Pin, an answer box), a scroll bar (`onScrollbar()`: `#body`'s, or the own sideways bar of a code block or `pre` line; a table never scrolls sideways, its cells wrap) and the second or third press of a double or triple click (`detail` 2+, read on `mousedown`: a `pointerdown`'s is 0), which select a word or a paragraph natively (Ctrl+C copies them); anything else draws the rectangle once the pointer has gone `AREA_MOVE` 4 px. Its `mousedown` is `preventDefault`ed (no selection starts) and any selection left is cleared; a focused answer box is blurred as such a press always did. A press released in place stays a click: `clickAction()` opens the paragraph's box, a link opens. A drag inside an answer box selects its text. `#replies` shows the arrow, not the I-beam (`.ans` keeps it).
- `#area` (in `#body`, `position: absolute`, `#body`'s scrolled coordinates, so it scrolls with the replies; z 5, `pointer-events: none`): 1.5 px blue border with `--r-ctl` 10 px corners (as the frame's), faint blue fill, there only while the drag lasts. ## Pins
- Pin (`.rpin`, the strip's Pin look: 20 px, `--r-small`, blue filled when on) at the right of every reply's top line (`.rtop`: its time, now shown for a single reply too); tooltips *Keeps this reply as a chip under the tabs, after newer prompts and restarts* / *Unpins this reply: its chip under the tabs goes*. A click calls `ReplyApi.pin(sid, id, text, mode)` (`pin`, `unpin`, `swap`) → `reply_pin()`, which takes the reply's text and time from the transcript (the page's copy when the transcript no longer holds it) and answers `{pins}` or `{full, pins}`.
- Store (`agent-reply.py` `Pins`, `~/.claude/state/agent-panel/reply-pins.json`, `{sid: [{id, at, text, pinned}]}` in pin order, a lock for the API thread): the reply's own text, so a pin stays through newer prompts, compaction and a transcript read again; per session id, kept after the session closes and shown again with its tab; `PIN_MAX` 8 per session (`add()` answers `added`, `already`, `full` without a change, `empty`); `swap()` drops the oldest pin and adds; read back clean at start (bad entries dropped, the last 8 kept). Deleted with the state folder by `uninstall.py`.
- Chip row (`#chips` in the head, `drawChips()`, only while the shown session has pins; 28 px chips, `--r-ctl`, the shown one outlined as a tab): **Latest** first (*Shows the replies since your last prompt*), then a chip per pin in pin order: pin glyph, `pin_label()` (the first 5 words of the first line with text, markdown's marks dropped, cut at 32 characters, `…` when cut), the reply's time (`HH:MM`, `DD Mon HH:MM` when not today; `pins_of()`), and an x (*Unpins this reply. Its chip and the text kept with it go*). Chips wrap into more rows.
- A chip shows its pinned reply in place of the latest ones (`view`, page-side; `shownReplies()`), with the same answer boxes (draft keys are the message id, so an answer typed there is a draft as any), selections marked in it, Copy and Send to Session. Back to the latest: **Latest**, a press on the shown session's tab, or another session shown (a tab, a typed prompt, a terminal followed); following the terminal of the session already shown keeps the chip. Unpinning the pin shown goes back to Latest. A press on the head leaves a focused answer box first, so the chip or tab press redraws at once.
- Limit: Pin on a 9th reply shows `#ask` under the head (amber line, no dialog): "A session keeps 8 pins at most. Unpin the oldest, “<words>” (<time>), and pin this one?" with **Unpin Oldest and Pin** (`swap`) and **Cancel**; it goes with Cancel, a pin change or another session.

## Limits
- Reply to a passage: numbered lists and the reply window need the panel running and shown with strip and keeper on (otherwise bare `:` quotes the clipboard and `:N` matches nothing). Only a selection tied to exactly one session is listed: none from outside a session's terminal or from a tab whose title does not show its name; none from a Linux `claude` inside WSL. A chance ` :2 ` outside code quotes entry 2 if listed. Hiding the panel or switching the strip off empties every list. A selection cannot be dropped by hand; a prompt empties the list. A `:N` with at least 16 characters round it that also stand in a listed passage or one of Claude's last 40 text blocks counts as quoted text, so typing a long stretch of a reply's own example verbatim is not a marker. Without `copyOnSelect` (or Ctrl+C) a `:` quotes whatever was copied before. Console (conhost) windows were not tested.
- Reply window: needs the panel running with the strip shown; only replies that ended a turn (text Claude writes between tool calls is not shown); not for a session Codex holds; a session's window changes only when its turn ends. Send to Session types only into the session's own terminal window whose title shows Claude Code's glyph (with several session tabs, its own tab must come to the front), needs the paste key (`paste_keys` on), inserts at the cursor (text already in the prompt stays and is not read), never presses Enter; a line over 5 KiB may meet Windows Terminal's large-paste question (not tried). Answers to replies a newer prompt replaced are dropped. The tab follows a terminal only after the panel has found its window (a scan, every 15 s, after the session opens); pins not tried on the live panel; an area's answer only within one reply; the follow and Send to Session end to end only on conhost windows the test made, not in Windows Terminal (`trials.md`).
