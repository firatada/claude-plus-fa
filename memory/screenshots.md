# claude-plus-fa: screenshots and the paste key

What is true now; history in [`trials.md`](../trials.md). Limits of these features are in [`limits.md`](./limits.md).

## The keeper
- `agent-panel-shots.py`, class `Shots`, loaded by the panel (`load_shots()`, `importlib`) on two threads; a missing or broken file leaves the panel running without it. Fed the open, non-headless sessions on every live pass and scan (`feed_shots()`: id, transcript, `where_of()` as project folder, title). Off with `"screenshots": false`.
- Only screenshots the user takes: a message-only window (`claude-plus-fa screenshots`) with `AddClipboardFormatListener`; on each change it reads the owner and its image name, the formats (`GetUpdatedClipboardFormats`, no `OpenClipboard`) and the process list.
- A screenshot = a bitmap or PNG and: the owner is a snipping tool (`ScreenClippingHost.exe`, `SnippingTool.exe`, `ScreenSketch.exe`); or the owner is `svchost.exe` (the clipboard broker) while a snipping tool runs or ran within `SNIP_RECENT` 5 s; or no owner and nothing but `CF_BITMAP`, `CF_DIB`, `CF_DIBV5`, `CF_PALETTE` (PrintScreen). Clipboard history's marker formats are ignored; a clipboard with the paste mark is skipped. Read with Pillow `ImageGrab.grabclipboard()`; never written.
- Saving: a capture waits `HOLD` 3 s; if Windows writes the same picture as a file meanwhile, the file is kept; otherwise `<Desktop>\screenshots\<app>_<title>_YYYY-MM-DD_HHMM.png` (`_2`, `_3` on a clash). The same picture again within 10 minutes is not saved twice. The folder is made at the first save.
- Name: `<app>` = exe name lower case (ApplicationFrameHost gives the framed child's), `desktop` for Progman/WorkerW; `<title>` = window title (`InternalGetWindowText`) without the app's own name at the end (by exe name or `ALIAS`), slugged to 40 characters, left out when empty.
- Which window (`taken_in()`): for a snip, the window under the middle of the dragged box (`follow_drag()` polls the button and pointer every `DRAG_POLL` 15 ms while a snipping tool is in front, at most 120 s; `snipped()` uses it when it ended within 5 s; `window_at()` walks the z-order skipping hidden, cloaked, minimised and transparent windows and those `describe()` refuses); otherwise the foreground at the clipboard change if a screenshot can show it; otherwise the last window remembered by `Shots.front()` (fed by the panel's foreground hook, skipping the panel, taskbar, Alt+Tab and snipping tools); else the time alone.
- Windows' own files: the Screenshots known folder and `%OneDrive%\Pictures\Screenshots` listed every second; a new PNG is moved to the Desktop folder once its size holds still and it decodes, named by its write time; it replaces a clipboard twin only when the pixels are identical.
- Pastes: each open transcript tailed by offset, only lines holding `"imagePasteIds"` parsed. Match: a 24 x 24 colour thumbnail (`sig()`) against the remembered ones, same shape required, mean channel difference under `MATCH` 6; an identical unshrunk PNG wins; else among matches within `CLOSE` 1.5 of the best, the latest captured before the paste.
- Placing: the first paste moves the file to `<project>\screenshots\<title-slug>_YYYY-MM-DD_HHMM.png` (session title in ASCII, at most 40 characters); a paste into another project copies it; the same project again does nothing. Project = the session's home folder (`where_of`), not the paste's `cwd`. `place()` lists the new path in `places` before moving.
- Ignore files: `.gitignore` gets `screenshots/` unless already ignored (created only inside a git work tree), `.assetsignore` likewise but only if it exists; line endings follow the file. The only project files it edits; nothing is deleted.
- `saved_file()` (used by the paste key): the keeper's own file for a picture (same size, thumbnail within `SAME` 1.0, pixel-identical file, newest first).

## The strip and preview
- `agent-shots.html` in a third pywebview window (`SHOTS_TITLE` *Field Agents Screenshots*), hidden at start, `focus=False`, frameless, `min_size=(0, 0)`, `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` (`float_style()`); edged as the panel on the right: `shadow=True` (DWM's frame: square corners, 1 px border, its shadow), no window region (DWM ignores one), and no edge of its own in the page (`#strip` padding 6 px = `SHOT_PAD`); an owned window of the panel (`GWLP_HWNDPARENT`, set in `update_strip()` before the first show), so it rises and sinks with the panel; every `SetWindowPos` on it carries `SWP_NOZORDER`; hidden whenever the panel is hidden.
- Fed by `update_strip()` (`shotStrip.update(items, cols)`, `shotStrip.open`); calls `StripApi` `<ready, press, release, enlarge, copy, pin>`. It holds the screenshots alone; while a session is open the reply window (tabs, the line naming the session, the replies) stands left of it as a window of its own, one width with a full row of the strip: [`reply.md`](./reply.md).
- Shows `Shots.latest(3, pins)`: every pinned screenshot that still exists in pin order, then the last three unpinned whose file exists, newest first, each at `where(e)` (Desktop file, else a project copy).
- Pins: *Pin* in each card's top row (on: filled `--blue`, white text, `aria-pressed`); `pin:<at>` → `toggle_pin()` → `"shot_pins"` (`save_pins()`; read at start by `strip_pins()`, which drops repeats and non-numbers and writes the cleaned list back); handed to the keeper as `Shots.keep`. Pins whose screenshot is no longer `Shots.alive()` are dropped at every `update_strip()`.
- Numbers (`num`): the recent ones counted from the newest (1 = newest), the pinned by pin order; badge `.num` at the left of the top row (16 px dark pill, white 10 px bold; the pinned one led by a pin glyph), `pointer-events: none`; the preview's head shows the same badge (`#badge`), refreshed through `feed_view()`.
- Card: `SHOT_W` 150 logical px wide, as tall as `card_h()` (below; `--h` in the page), white, 1 px `--line` edge, 8 px corners, text only (no picture), compact since 2026-11-25: a top row (badge, *Pin*, *Copy* at the right end, 20 px), the title in 11/13 px semibold on the lines the height leaves (`--lines` = (h − 29 − 12 − 5) / 13, 2 at 73 px) then an ellipsis, the time in 10/12 px `--muted` right under the title, no space between. The whole card opens the preview.
- Label (`shot_label()` in the `.pyw`, from the file name alone): title = the last `_` part before `YYYY-MM-DD_HHMM`, a clash's `_<n>` ignored, hyphens as spaces; time `HH:MM` today, `yesterday HH:MM`, `3 Nov HH:MM` this year, `3 Nov 2025 HH:MM` before (English, `lang="en"`); a name outside the pattern shows its stem and modified time. Part of the strip's key, so it turns over at midnight.
- Pointing at a card shows the full file name in the panel's tooltip style, centred on the card, foot 2 px above the time.
- Layout (`strip_rect(n, head)`, widths from `band_layout()`): grows left from its top-right corner (`strip_anchor()`) and wraps into rows below; window `SHOT_PAD` 6 + cols x (150 + 6) by 6 + rows x (card + 6) logical px rounded up. Card height (`card_h(head)`, sent as `shotStrip.update(items, cols, h)`, part of the strip's key): with a session open, the reply window's head (`head_h`, measured by its page and sent as `ReplyApi.size(h, head)`) less 2 x `SHOT_PAD`, so one row of the strip is exactly as tall as the head (85 → 73; tabs in two rows 137 → 125; pins 119 → 107; folded 84 → 72) and the two windows' edges line up; a new head height fires `reply-head` → `update_strip()`; at least `SHOT_MIN` 60. Without a session open, or before the head is measured: `SHOT_H` 73. Wrapped rows take the same height. Without a session open: as many columns as fit to the screen's left edge. With one: the strip and the reply window share one width `w` = the reply window's width (`REPLY_W` 820, or the user's `reply_width`: [`reply.md`](./reply.md) § The reply window: where and when, Resize), or half the room less `SHOT_GAP` when narrower (the room runs to the screen's left edge, where the reply window stands flush: 812 on a 1920 px screen with the panel docked right); columns = as many as `w` holds; a full row makes the window exactly `w` wide and `#shots` (grid, `repeat(--cols, 150px)`, `justify-content: space-between`) spreads the 150 px cards over it, every row on the same columns; fewer screenshots than a row keep their own width; when `w` holds under two columns, one column and the reply window keeps `REPLY_MIN`. No screenshot: hidden. Clamped wholly into the nearest monitor's work area (`MonitorFromRect`) without rewriting the saved place.
- Place: `"shot_strip_at"` when dragged; with the panel docked right, the default is `SHOT_GAP` 8 px left of the column and flush with the monitor's work-area top. With the panel docked on top, the default is immediately below the panel's tab bar at the right.
- Drag: a press anywhere on the strip (or on the reply window's head) calls `press()`, which starts `strip_follow()` (polls button and pointer; moves after `SHOT_MOVE` 4 px with `SWP_NOACTIVATE`; saves the place on release). `release(n)` tells the page whether press n became a drag; only a press released in place is a click.
- Redrawn when `Shots.version` changes (polled every 0.2 s), on every scan and on toggle and dock changes. Hidden when switched off, the keeper is off, or no screenshot is left.
- Switch: a picture-icon button just left of the hide button (blue while on, gone while the keeper is off) → `toggle_strip()` → `"shot_strip"`.
- Preview: a fourth window (`VIEW_TITLE` *Field Agents Screenshot*, the same page with `window.MODE = "view";` at `/*MODE*/`), topmost, not owned; fed by `feed_view()` and `view_show()` (`shotView.update / show / hide`), calls `ViewApi` `<ready, open, copy, copy_image, delete, close>`. It holds the strip's pictures at full size as data URLs (`full_src()`, cached by path, size and mtime), decoded ahead, so a click only switches and places it.
- Preview size: the picture up to its own pixel size (`pic_size()` from the file header) in the largest of the four areas of the strip's screen free of the strip, `VIEW_MARGIN` 24 px from edges and strip, at least `VIEW_MIN_W` 480 px wide, a `VIEW_HEAD` 36 px head (badge, file name, then *Delete*, *Copy as Text*, *Copy as Image*, *Open*, 24 px, top right) and `VIEW_PAD` 8 px round the picture. Its card is outlined in the strip.
- Preview closes on: a second click on the same card, a click on the preview, *Open* (then `os.startfile`), *Delete*, Esc, a press of any button outside the preview and strip (`Outside`: `WH_KEYBOARD_LL` and `WH_MOUSE_LL` on their own thread, installed before it shows; `Outside.inside()` uses the root of `WindowFromPoint`), a strip drag, or its picture leaving the strip. Esc is swallowed while it shows.
- Delete: `view_delete(at)` looks the path up (`Shots.path(at)`), sends it to the Recycle Bin (`recycle()`), marks the entry `dropped` (`Shots.drop(at)`), closes the preview; a refusal leaves everything and shows *Failed* in `--red-deep` for 1.6 s. No confirmation.
- Copy as Text (the strip's *Copy* and the preview's *Copy as Text*, one `copy(btn, at)`; `ViewApi.copy` is `StripApi.copy`): `Shots.copy_text(at)` puts `[screenshot: <path>]` plus the picture's OCR text on the clipboard as `CF_UNICODETEXT` alone (the path line alone when no text); *Reading…*, then *Copied* (`--green`) or *Failed* for 1.6 s, then the button's own label. `aria-label` "Copy the path and text of <name>". The strip's cards keep this one *Copy*: no room on a 150 px card for a second button, and the picture is one click away.
- Copy as Image (preview only, `copy(btn, at, "copy_image")` → `ViewApi.copy_image` → `Shots.copy_image(at)`): `image_formats(path)` → `set_clipboard()`, in this order: `PNG` (the file's own bytes, else encoded), `CF_DIBV5` (32 bit `BI_BITFIELDS`, straight alpha, `LCS_sRGB`, bottom-up), `CF_DIB` (24 bit, alpha laid on white, rows padded to 4 bytes), the paste mark (so the keeper skips it); Windows makes `CF_BITMAP` (Paint) at the picture's own size. *Copying…*, then *Copied* or *Failed* for 1.6 s. `aria-label` "Copy the picture of <name>". The paste key then finds the keeper's own file (`saved_file()`) and pastes its path.
- Preview buttons: `#del`, `#copy`, `#copyimg`, `#open`, one 24 px height; `#copy` `min-width` 86 px and `#copyimg` 96 px (their own labels), so the feedback never moves a button.

## Copy text (OCR)
- `Ocr` in `agent-panel-shots.py`: one Windows PowerShell 5.1 kept resident (script `OCR_PS`), started with the keeper, killed by `stop()`, gone when the panel dies (stdin closes). It loads WinRT, makes the engine with `TryCreateFromLanguage('tr')` (`OCR_LANG`), else the user profile languages, warms up on a blank bitmap, prints `READY`, then answers each `<path><TAB><times>` line with the factor and one `x<TAB>y<TAB>w<TAB>h<TAB>text` line per word, ended by 0x1E.
- Reads a picture only on Copy. A worker that died or does not answer in 30 s is killed and restarted at the next Copy.
- Recognition: read as is; when the words are fixed pitch (`fixed_pitch()`: median spread of width per letter under 3 %) read again `OCR_UP` 3x larger, cubic, within 10000 px a side (`MaxImageDimension`) and 25 MP.
- `ocr_rows()` rebuilds the text from word boxes: rows by vertical position across the whole width; no space where boxes nearly touch (under half the usual gap); a blank line where the gap exceeds 1.6 row pitches; a row is joined to the one above when nothing separates them, it opens no list item, it starts where the row above (or its text) starts, and its first word would not have fitted at the end of the row above, only on a picture where at least two rows end that way; on a picture with a numbered list a leading `14,` or `14 ,` becomes `14.`. Nothing else is corrected.

## Paste key
- `agent-panel-paste.py`, its own process (`pythonw agent-panel-paste.py <panel pid>`), started and watched by the panel's `watch_paste()`; one instance (mutex `Local\claude-plus-fa-agent-panel-paste`, message-only class `claude-plus-fa paste`); ends with the panel (`follow_panel()`).
- Registers Ctrl+V and Alt+V (`RegisterHotKey`, exact modifiers) only while the foreground window is in `paste-windows.json` (written by the panel's `find_windows()`) and its title is Claude Code's `<glyph> <name>` (`claude_title()`). Follows the foreground (`EVENT_SYSTEM_FOREGROUND`), the front window's title (`EVENT_OBJECT_NAMECHANGE`) and looks again every second.
- On a key with a picture and no text on the clipboard (`image_only()`): keys unregistered; a worker reads the picture, takes the keeper's own file (`saved_file()`) or writes a PNG (`compress_level=1`) to the temp folder; `save_clip()` copies every format; the path goes on as delayed-render `CF_UNICODETEXT` beside the mark `claude-plus-fa paste` and the three quiet formats; Ctrl+V is sent (`keys_for(paste=True)`).
- `WM_RENDERFORMAT` from the terminal's own process renders the path; any other process asking gets nothing. The saved formats then go back with the mark and quiet formats, unless another program set the clipboard meanwhile. The terminal gets at most `READ_WAIT` 2 s.
- Otherwise (text, nothing, no session window in front): keys unregistered, the same combination sent, keys back after `REARM` 80 ms.
- Restored: every memory format (`CF_DIB`, `CF_DIBV5`, `PNG`, `HTML Format`, `Preferred DropEffect`, registered byte formats) and `CF_ENHMETAFILE`; lost: OLE `DataObject`, `Ole Private Data`, `CF_METAFILEPICT`, `CF_PALETTE`, owner-display, private and GDI formats, OLE-stream data.
- Claude Code (2.1.329) attaches a pasted full path of an existing `.png/.jpg/.gif/.webp` as `[Image #N]` at the cursor and adds a `[Image: source: <path>]` text block; only a missing file falls back to its PowerShell.
- Stall guard: `watch_paste()` sends `WM_NULL` once a second (`SendMessageTimeout`, `SMTO_ABORTIFHUNG`, `PASTE_ANSWER` 700 ms); two misses in a row: kill and restart (`PASTE_RESTART` 10 s between starts), as when it died.
- Each paste and pass-through is logged to `paste.log`. Off: `"paste_keys": false` (process closed).
