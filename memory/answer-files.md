# claude-plus-fa: pictures and files in an answer box

What is true now; history in [`trials.md`](../trials.md) (2026-11-26, 2026-11-27). Asked 2026-11-26: whatever can be pasted into the Claude Code prompt can be pasted into an answer box, and reaches Claude with the answers as it would from the terminal. Asked 2026-11-27: it goes in at the caret, inside the sentence, never in a row under the text, so where it stands says which words it belongs to. The rule: the maintainer's mindmap page `answer-in-place.md`; its specimen `specimens/answer-in-place.html` makes the same choices.

## What the terminal takes (Claude Code 2.1.332 on this PC, measured in sessions of their own in a hidden pseudo-console, `tools/paste-place-trial.py`)
- Text: typed as is; a long paste shows folded as `[Pasted text #N +M lines]`, goes whole, and is stored wrapped in `<pasted_content>` ([`gotchas.md`](./gotchas.md)); a short one (3 lines) goes in as typed text.
- A paste that is only the path of an existing `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp` (quoted when it holds a space) becomes `[Image #N]` at the caret, inside the sentence, the picture attached as an image block; Claude names the word before each picture right (two pictures in one sentence; typed words around them, or pasted pieces, or after a folded `[Pasted text #N]`; pastes 0.3 s apart are enough). `#N` counts the session's pastes, pictures and folded texts together.
- Within one paste of several lines, lines that are only such a path are taken out and their pictures put at the start of the prompt (`[Image #1] [Image #2]The word …`); Claude then cannot tell which words a picture belongs to unless the text says so (it says so: "both pictures are at the very start"). A line holding text besides the path stays text; blank lines of such a paste are dropped. Any other path stays text; Claude reads it with a tool.
- A picture on the clipboard: **Alt+V** (the binary's default `chat:imagePaste` on Windows; Ctrl+V only on WSL) attaches it as `[Image #N]` at the caret. Ctrl+V is Windows Terminal's paste: a clipboard with no text pastes nothing there; the panel's paste key turns it into a path ([`screenshots.md`](./screenshots.md) § Paste key). Not measured here: Alt+V itself (it would have used the maintainer's clipboard).
- Files copied in File Explorer and files dragged onto the terminal: Windows Terminal pastes their paths (its `TerminalApp.dll` imports `DragQueryFileW`; not run here).

## The box
- An editable line (`<div class="ans" contenteditable="true">`), not a textarea, so a picture or file stands in its text. Its value is the text with each picture or file as a token, `<path>` (`TOK()`, `TOKS`; `agent-reply.py` `TOKEN`). `boxify()` gives the box a textarea's `value`, `selectionStart`, `selectionEnd`, `setSelectionRange()` and `select()` in value offsets (`boxItems()`, `val()`, `offsetAt()`, `posAt()`, `selOf()`, `setSel()`), so dictation, quick answers and Esc work on it as before. A selection is remembered while the box lacks the keyboard (`_sel`, kept on `selectionchange`); `focus()` alone puts the caret back there (its end the first time). `.blank` while it holds nothing (the placeholder is `::before` from `data-ph`; the quick answers show only then).
- Chip (`.ic`, `chipHtml()`, `contenteditable="false"`): 19 px high in the line, a 14 px thumbnail (`<img>` from `fileUrl()`, the page being a `file:///` page) or a file glyph (also for a picture whose file is gone), and its number from `data-label` (`labelChips()`: pictures and files counted apart through every box shown, in reading order, the same path keeping its number, as the sent text numbers them; the later ones renumber when one goes). Tooltip: its path. A click opens it as a file link in a reply opens (`ReplyApi.link`); a press keeps the keyboard in the box. Backspace and Delete take it out like one character, Ctrl+Z brings it back; arrows put the caret on either side of it; typing goes on after it.
- Text on the clipboard (`text/plain` not empty): goes in as plain text (`boxInsert()`; markup never), as before. Ctrl+B, Ctrl+I, Ctrl+U and any `format*` input do nothing. Shift+Enter is a line break (`insertLineBreak`), never a block.
- No text (a screenshot, an image copied in a browser, files copied in File Explorer): `paste_clip("any")` → `agent-reply.py` `clip_files()`: `PIL.ImageGrab.grabclipboard()`; a list of files → those that exist, as their own paths; a picture → saved as a PNG (`save_picture()`, `compress_level=1`) in `FILES` `~/.claude/state/agent-panel/reply-files/answer-YYYYMMDD-HHMMSS-mmm.png` (`-2`, `-3` on a clash). They go in where the caret was when the paste began (`insertChips()`, the caret put after the last one by value offset, since Chromium leaves it before a chip that ends the line). Nothing usable: a note under the box ("Nothing to paste: no text, picture or file on the clipboard.").
- **Alt+V** in a box: `paste_clip("image")`, the picture alone (a copied picture file counts), also while the clipboard holds text; else "No picture on the clipboard."
- Copy or cut inside a box: `text/plain` gets the part with each chip as its path, and `text/x-claude-plus-answer` the value with its tokens, so a paste back into a box brings the chips.
- Drop (`dragover`, `drop` on the window, only when the drag holds `Files`; every such drop is `preventDefault`ed, so the window never opens a file itself): onto a box, where it is dropped (`caretRangeFromPoint`); onto a paragraph, its box opens and they go at the end of its text; tinted while over it (`.dropping`). The page posts the files to WebView2 (`chrome.webview.postMessageWithAdditionalObjects("FilesDropped", files)`, as pywebview's own drop does), so pywebview's `webview.dom._dnd_state["paths"]` gets their real paths; `ReplyApi.dropped(names)` takes those named (by file name, waiting up to `DROP_WAIT` 1 s). pywebview records them only while a drop listener is counted: `drop_state()` counts one when the reply window is made. A dropped picture with no file behind it (a browser's) is read as a data URL (up to `DROP_MAX` 25 MB) and saved by `ReplyApi.save_image()` → `picture_from_data()`; anything else gets the note "Only pictures and files from this PC can go in an answer." Text dragged into a box goes in as plain text where it is dropped; a drag inside the box itself moves as usual.
- While the panel reads the clipboard or a drop, the page may redraw: the box is found again by its key (`boxNow()`; a paragraph's empty box opened again).
- At most `FILES_MAX` 20 different paths a box (`addPaths()`); the same one may stand twice. An answer is its value (`filled()`): a box with only a picture is an answer, counts in the footer, is not closed as empty, and is sent.

## Kept, sent, copied
- Drafts: `{text, passage, at, files}`; `text` holds the tokens where they stand, `files` the paths in it (kept for the sweep). A draft from before 2026-11-27 (its paths only in `files`) opens with them at the end of its text (`withLegacy()` in the page, `with_legacy()` in `agent-reply.py`).
- Copy and the area's copy (`with_files()`): each picture or file where it stands as its number, `[Image 1]` or `[File 1]` (`numbers()`, `number_of()`: per kind through everything copied, the same path keeping its number, so the chip's number), then one line per picture and file after the answer's text, `[Image 1: <path>]`; then, after a blank line at the end, each picture's path alone on a line (`image_tail()`, quoted when it holds a space), so a paste of it into Claude Code attaches them (at the start of the prompt, the naming line saying where each belongs; measured: named right, if with a remark about the leading markers).
- Send to Session (`reply_text(split=True)`, `send_pieces()`): the same text, but each picture stays a mark where it stands (no number, no naming line) and the paste is made in pieces: the text up to a picture, the picture's path alone, the text after it, ... The paste key's process pastes them one after another (`type_text()`, `PIECE_GAP` 0.5 s apart, the clipboard saved and put back once; it stops at a piece not read or once the terminal leaves the front), so each picture is Claude Code's own `[Image #N]` in its place in the sentence. Files keep `[File 1]` and their naming line. `reply-send.log` counts the pastes; Send to Session waits `SEND_WAIT` + `PIECE_WAIT` 1.5 s per piece after the first.

## Saved pictures
- Only the pictures the panel saved live in `reply-files/`; copied and dropped files are never copied, their own paths go.
- Swept (`sweep_files()`, from `reply_tabs()` at most every `SWEEP_EVERY` 600 s): a file there that a draft holds (its `files` or a token in its text) gets its time renewed; one no draft holds goes once that time is `FILE_KEEP` 24 h old, so a picture taken out of a box is there a day for undo and for a session that may still read its path. The whole folder goes with the state folder on uninstall.

## Limits
- The chip's number is the one Copy sends; in the terminal, Send to Session's pictures carry Claude Code's own numbers (`[Image #N]`, counted per session).
- Send to Session's pieces were measured as bracketed pastes into a hidden Claude Code; the paste key's pieces into a real Windows Terminal were not run end to end (the unit test drives `type_text()` with stand-ins).
- Files copied in File Explorer reach the box by the panel reading the clipboard itself; a drop on the live reply window was not tried here (the drop's WebView2 path hand-off is pywebview's mechanism, run only in its unit test with a stand-in).
