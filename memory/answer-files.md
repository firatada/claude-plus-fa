# claude-plus-fa: pictures and files in an answer box

What is true now; history in [`trials.md`](../trials.md) (2026-11-26). Asked 2026-11-26: whatever can be pasted into the Claude Code prompt can be pasted into an answer box, and reaches Claude with the answers as it would from the terminal.

## What the terminal takes (Claude Code 2.1.332 on this PC, measured in a session of its own in a hidden pseudo-console)
- Text: typed as is; a long one shows as `[Pasted text #N +M lines]` and goes whole.
- A pasted line that is only the path of an existing `.png`, `.jpg`, `.jpeg`, `.gif` or `.webp` (quoted or not, several on one line too) becomes `[Image #N]`: the picture attached as an image block. Within a longer paste those lines are taken out and their pictures put before the text (`[Image #1] [Image #2][Pasted text #3 …]`); a line holding text besides the path stays text; blank lines of such a paste are dropped. Any other path (`.txt`, a folder) stays text; Claude reads it with a tool.
- A picture on the clipboard: **Alt+V** (the binary's default `chat:imagePaste` on Windows; Ctrl+V only on WSL) attaches it as `[Image #N]`. Ctrl+V is Windows Terminal's paste: a clipboard with no text pastes nothing there; the panel's paste key turns it into a path ([`screenshots.md`](./screenshots.md) § Paste key).
- Files copied in File Explorer and files dragged onto the terminal: Windows Terminal pastes their paths (its `TerminalApp.dll` imports `DragQueryFileW`; not run here), so pictures among them are attached as above.

## The box
- Text on the clipboard (`text/plain` not empty): Ctrl+V types it, as before (the terminal's own way).
- No text (a screenshot, an image copied in a browser, files copied in File Explorer): the page's `paste` handler stops the paste and calls `ReplyApi.paste_clip("any")` → `agent-reply.py` `clip_files()`: `PIL.ImageGrab.grabclipboard()`; a list of files → those that exist, as their own paths; a picture → saved as a PNG (`save_picture()`, `compress_level=1`) in `FILES` `~/.claude/state/agent-panel/reply-files/answer-YYYYMMDD-HHMMSS-mmm.png` (`-2`, `-3` on a clash), its path. Nothing usable: a note under the box ("Nothing to paste: no text, picture or file on the clipboard.").
- **Alt+V** in a box (the box's capture-phase `keydown`): `paste_clip("image")`, the picture alone (a copied picture file counts), also while the clipboard holds text; else the note "No picture on the clipboard."
- Drop (`dragover`, `drop` on the window, only when the drag holds `Files`; every such drop is `preventDefault`ed, so the window never opens a file itself): onto a box, or onto a paragraph (its box opens), tinted while over it (`.dropping`). The page posts the files to WebView2 (`chrome.webview.postMessageWithAdditionalObjects("FilesDropped", files)`, as pywebview's own drop does), so pywebview's `webview.dom._dnd_state["paths"]` gets their real paths; `ReplyApi.dropped(names)` takes those named (by file name, waiting up to `DROP_WAIT` 1 s). pywebview records them only while a drop listener is counted: `drop_state()` counts one when the reply window is made. A dropped picture with no file behind it (a browser's image) is read as a data URL (up to `DROP_MAX` 25 MB) and saved by `ReplyApi.save_image()` → `picture_from_data()`; anything else gets the note "Only pictures and files from this PC can go in an answer." Text dragged onto a box drops as text, as before.
- Chips (`drawFiles()`, `.files` inside the box under its text; `grow()` gives the textarea a bottom padding of the chips' height + 10 px and places them 6 px above its bottom): 32 px, `--r-small`, `--line` border; a 24 px thumbnail (`<img>` from `fileUrl()`, the page being a `file:///` page) or a file glyph for anything else (and for a picture whose file is gone), the name (to 220 px with an ellipsis), an x (*Takes this picture/file out of the answer*); tooltip the full path. A click on a chip opens it as a file link in a reply opens (`ReplyApi.link`); its note, if any, under the box. Presses on chips keep the keyboard in the box. Out of the Tab order.
- A box's paths: `row.files`, each once, in the order they came, at most `FILES_MAX` 20 (`addPaths()`). An answer is its text and its files (`filled()`): a box with only a picture is an answer, counts in the footer, is not closed as empty, and is sent. The quick answers still show while the box has no text.

## Kept, sent, copied
- Drafts: `{text, passage, at, files}` (`files` only when there are any; `Drafts.put(sid, key, passage, text, files)`), so a box opens again with its chips after a redraw, a session switch or a restart; expired with its answer ([`reply.md`](./reply.md) § Drafts).
- Send to Session, Copy and the area's copy: each answer's text, then one line per path in the box's order, `[Image N: <path>]` or `[File: <path>]` (`with_files()`, N counting the pictures of the whole paste, the same picture keeping its number); then, after a blank line at the end of the text, each picture's path alone on a line (`image_tail()`, quoted when it holds a space). Claude Code attaches those pictures as `[Image #N]` and the `[Image N: …]` line says which answer each belongs to (measured end to end with the panel's own `reply_text()`: two pictures, one saved in `reply-files`, one in a folder with a space, reached the session as two image blocks and were told apart correctly). Pasted anywhere else the end lines are plain paths.
- `reply-send.log` counts the files sent besides the answers.

## Saved pictures
- Only the pictures the panel saved live in `reply-files/`; copied and dropped files are never copied, their own paths go.
- Swept (`sweep_files()`, from `reply_tabs()` at most every `SWEEP_EVERY` 600 s): a file there that no draft holds goes once it is `FILE_KEEP` 24 h old (the session may still read a path it was sent). The whole folder goes with the state folder on uninstall.

## Limits
- A picture's place in the answer is after the answer's text, not at the caret; in the prompt Claude Code shows the pictures before the pasted text.
- Blank lines of a paste that holds a picture's path are dropped by Claude Code (the quoted reply still reads, every line keeps its `> `).
- Files copied in File Explorer reach the box by the panel reading the clipboard itself; Windows Terminal's own paste of them and a drop on the live reply window were not tried here (the drop's WebView2 path hand-off is pywebview's mechanism, run only in its unit test with a stand-in).
