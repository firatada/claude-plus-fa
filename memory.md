# claude-plus-fa — memory

## Files and where they install
| Source | Installed to | Job |
|---|---|---|
| `glm.cmd` | `~/.local/bin` (on the user PATH) | runs `claude` against `https://api.z.ai/api/anthropic`, main model `glm-4.7-flash`, small model `glm-4.5-flash`. Shares `~/.claude`, so `glm --resume` sees every session |
| `glm-fallback.py` | `~/.claude/hooks` | `StopFailure` hook, matcher `rate_limit`. Silent unless the key file holds a real `CLAUDEX_KEY` (not empty, not the placeholder): without one, Yes would only send the conversation to z.ai to be refused. Asks in its own themed window (2026-11-09, per `mindmap/design.md` *No Native Popups*: pywebview + WebView2 with the panel's Spark tokens, shaped as a `design-dashboard.md` modal: title *Usage Limit Reached: <folder>*, an X, an amber note that the conversation goes to z.ai, *Cancel* and *Continue With GLM*, the latter focused; Escape, the X and Cancel all mean no; the window is sized to its content before it is shown and takes the foreground with a lone Alt press). Only if pywebview cannot be imported does it fall back to the Win32 message box. On Yes it opens `cmd /k glm --resume <sid> [--dangerously-skip-permissions] "<continue prompt>"` in the session's cwd |
| `statusline.py` | `~/.claude` | `statusLine` command: model · `ctx` bar · `5h` bar + reset time · `week` bar + reset day/time. Also writes `~/.claude/state/context/rate_limits.json` (the `rate_limits` object plus `at`, written to a `.tmp` and swapped in) for the Agent Panel. Bars green < 50 %, yellow < 80 %, red above. `5h`/`week` come from `rate_limits`, which only a claude.ai subscription sends, so GLM sessions show `ctx` alone |
| `prompt-recall.py` | `~/.claude/hooks` | `UserPromptSubmit` hook: writes the prompt to `~/.claude/state/context/<session_id>.prompt.json` (`{"prompt", "at"}`) and prints nothing, because a UserPromptSubmit hook's stdout is added to Claude's context. Skips prompts that start with `<task-notification>` or `<system-reminder>`: Claude Code delivers a finished background task through this hook as if the user had typed it, and it used to replace the real prompt on the status line (fixed 2026-10-20). `statusline.py` shows it in full under the bars as `› HH:MM  <prompt>`: whitespace collapsed, wrapped to the console width (read from `CONOUT$`, since Claude Code passes no width and stdout is a pipe; 120 if that fails), at most `PROMPT_LINES` = 12 lines, the last one ending in `…` when cut. Claude Code trims every status line, so the continuation indent starts with a colour code to survive the trim. Changed from a single cut line on 2026-10-07 at the user's request: the prompt must be readable in full |
| `context-guard.py` | `~/.claude/hooks` | one script, four modes: `stop` (Stop: at ≥ 90 % context, once per climb, exit 2 with the documentation steps; re-arms when usage falls under 50 %), `precompact` (PreCompact: stdout becomes extra compaction instructions), `resumed` (SessionStart matcher `compact`: tells Claude to read `handoff.md` and `memory.md` when present, then run the resume steps; the same session continues, so this is where the 90 % documents get read back), `started` (SessionStart matcher `startup|clear`: if the cwd has `handoff.md`, tells Claude its date and to read it and `memory.md` first; silent otherwise; `--resume` needs nothing because the conversation comes back). `resumed` and `started` answer in JSON: `systemMessage` tells the user which files will be read (or, after compaction, that no handoff.md was found), `additionalContext` tells Claude to read them and then name the files it read in one line |
| `agent-panel.pyw` | `~/.claude`, started by `pythonw.exe` from `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `ClaudePlusFA agent panel` | Windows app (pywebview showing `agent-panel.html` in WebView2, tray via `pystray`): every session, newest first, an ordinary window over the right edge of the work area, 280 logical px wide, not topmost: it reserves no space, so desktop icons and maximised windows keep their place and the active window covers it. `Ctrl+Alt+C` or the tray raises it when covered, hides it when it is in front, shows it when hidden. A click runs `claude --resume <id> --dangerously-skip-permissions` in a new console in the session's folder: `cmd /k` normally, PowerShell for a UNC folder (`\wsl.localhost\...`, cmd cannot stand in one), `wsl.exe --cd` for a session found inside a running WSL distro's own `~/.claude`. A single click raises an open session; a closed one opens on a double click |
| `agent-panel.html` | `~/.claude`, beside the `.pyw` | The panel's whole look and its input handling. Python pushes the state with `app.update(<json>)` (only when it changed) and the page calls `window.pywebview.api.<ready, click, open, set_hidden, close, delete, hide>`, each returning the line shown at the bottom |
| `mascot/` + `tools/mascot-export.py` + `tools/mascot-source/purple-octopus.png` | `~/.claude/agent-panel-mascot` (replaced whole on install) | The Agent Panel's octopus: 4 WebP strips of 96 px frames, about 87 KB in all: `calm` (5 frames), `reading` (5), `asking` (4), `sleeping` (3). Cut by `python -I tools/mascot-export.py` from the maintainer's sheet (1536 x 1024, transparent, two columns of six numbered rows with five poses each and a label pill per row; the script removes the pill, splits frames on the gaps between drawings, stands each on a shared square on its baseline). Which rows and frames each strip uses is the `STRIPS` table there; the frame counts are repeated in the page's `MOOD`. It also writes `mascot/logo.png` (256 px, the calm first pose cut close to its drawing): the package's logo, shown at the top of the README and and `mascot/tray.png` (64 px: a square 0.86 of the logo wide from the drawing's top, centred on the head, trimming only the tentacles' outer tips), the tray icon through `agent-panel.pyw` `logo_image()`. The maintainer, 2026-11-09: the full logo was a speck at 16 to 20 px, a head close up (two thirds wide) broke into pieces; 0.86 was picked between them; the old blue Spark tile drawn in code stays as its fallback. `docs/agent-panel.png` is the README's panel screenshot, taken from the real page fed made-up sessions (never real session names) at 280 px wide, 2x. `agent-panel.pyw` inlines the strips into the page as `window.MASCOT` data URLs (the page is handed over as a string and cannot load files); without the folder the page keeps its old blue logo and shows no mascot. |
| `install.py` / `install.cmd` | — | copies the files, adds `~/.local/bin` to the user PATH if missing, registers the hook in `~/.claude/settings.json` (backup `settings.json.before-claude-plus`), sets `statusLine` only if none exists or it is already ours, creates the key file with a placeholder if missing and prints a one-line optional note; it never opens Notepad (until 2026-10-28 it did, on every install and update, which read as if the key were required; everything but the GLM switch works without it) |

Branches (2026-10-06): `main` is the public branch, tracking `origin` = https://github.com/firatada/claude-plus-fa (renamed from `firatada-ctrl/claude-plus` on 2026-11-09, repo and account; GitHub redirects the old URLs); it started as one squashed commit, "Initial public release". `history` is local only and holds the full development history up to that release (old commits carry personal paths and session links, so it is never pushed). Work on `main`. Every push needs the maintainer's approval; before one, scan what goes out for keys (the release was checked against the real z.ai key and the GitHub token, with no finding).

Public and personal behaviour (2026-10-06): one code base, published as `firatada/claude-plus-fa` under MIT. `context-guard.py` carries built-in steps (`WARN_STEPS`, `RESUME_STEPS`) in its `stop` and `resumed` messages. `~/.claude/claude-plus.local.json` with `{"rule": "<where your steps live>"}` replaces them with "run the ... steps in <rule>"; a missing, unreadable or non-object file falls back to the built-in steps. The installer never writes that file. The maintainer's copy points at the global CLAUDE.md, section "Never let unwritten knowledge accumulate", which holds a richer procedure (mindmap page, rules to propose). Two branches or two repos were rejected: every fix would have to be carried twice and the copies drift.

Uninstall (2026-10-07): `uninstall.cmd` / `uninstall.py` removes every hook whose command names one of the three scripts, keeps any other hook in the same event, drops events and `hooks` left empty, removes `statusLine` only when it names `statusline.py`, then deletes the five installed files and `~/.claude/state/context`. Backup first: `settings.json.before-claude-plus-uninstall`, written only when something changes. Kept on purpose: the key file, `claude-plus.local.json`, the install backup, and `~/.local/bin` on PATH (other tools live there). Tested in a fake profile (USERPROFILE override, install via `install.copy_files()` + `register_hook()` so the real registry PATH is untouched): with and without a foreign status line, a foreign Stop hook survived, a second run reported nothing to do. Never run it on the maintainer's own profile as a test.

Key file: `~/.claudex/profiles/glm/.env`, line `CLAUDEX_KEY="..."`. Never in this repo. The path is claudex's, so `claudex validate glm` works on it; glm.cmd itself does not need claudex.

## Behaviour
- Session panel (2026-11-07): sessions are the `<uuid>.jsonl` files directly under `~/.claude/projects/<folder>/` (subagent and set-aside transcripts excluded), plus the same under each WSL distro that is already running (`wsl -l --running`; the panel never starts one). Title: the last `custom-title` (`/rename`), else the last `ai-title`, else the first real prompt. A session must be resumed from the folder its transcript is filed under, and a session that moved (`/cd`) lists several `cwd`s, so the panel picks the `cwd` whose slug (every non-alphanumeric character as `-`) equals the folder name. Open sessions come from `~/.claude/sessions/<pid>.json` (`sessionId`, `status` busy/idle/shell, `name`) when that pid is alive. Parsed results are cached in `~/.claude/state/agent-panel/cache.json` by mtime and size; a rescan every 15 s takes about 0.05 s.
- The panel was called "session panel" (`session-panel.pyw`) until it became the Agent Panel on 2026-11-07, at the maintainer's request. The installers stop a copy under either name and delete the old file, sign-in entry and state folder.
- Right-click menu (2026-11-07, the maintainer's spec): Hide / Unhide, Close (open sessions only), Delete. The menu is HTML inside the panel (a web page cannot draw outside its window), opened at the pointer and kept inside the panel; Delete is red on a pale red hover. It closes on Escape, on a click outside (that click does nothing else), on scroll and on focus loss. The native menu was rejected (the maintainer, 2026-11-08: it ignores the theme). Hidden ids live in `~/.claude/state/agent-panel/hidden.json`; Hidden sessions, sessions whose folder is gone and headless runs (`entrypoint` `sdk-cli` in the transcript: a `claude -p` that another session started, e.g. tech news calling the Topview MCP; 2026-11-08, the maintainer) stay out of the main list and the header count; a headless card says `headless` and its menu has no Hide; the quiet link *Show Hidden, Deleted and Headless (n)* in the strip under the list adds a HIDDEN, DELETED AND HEADLESS section after the main list and scrolls to it. Cards there are not greyed; their second line says `hidden` or `folder deleted` (the maintainer, 2026-11-07: greyed cards inside the main list read as clutter; the user's word is "deleted", not "missing"). Open/working dots are refreshed every 2 s from `~/.claude/sessions/<pid>.json` alone (the full transcript scan stays at 15 s), so a session closed in its own terminal loses its dot within 2 s. Close and Delete confirm in two steps beside the control, per `mindmap/table.md` *Delete confirmation* (2026-11-08, replacing two modal dialogs): the menu turns into a small card with the question, one sentence on what happens, Cancel (focused, the default) and *Yes, Close* / *Yes, Delete*, placed under the card (above it near the bottom), never on it. Delete on an open session closes it first and waits up to 10 s for its process to end (`close_delete`); on a session stored inside WSL it is shown greyed and says why under itself (a network path has no Recycle Bin). It then moves the transcript, its `<id>/` folder and `file-history/<id>/` to the Recycle Bin with `SHFileOperationW` (`FOF_ALLOWUNDO`). Project files and the project's auto memory are never touched. Close sends `WM_CLOSE` to the session's window when no other open session shares it, otherwise ends the process; the transcript stays.
- Tested 2026-11-07: work area back to the full 1920 px with the panel running; a maximised window spans the full width and covers the panel; Ctrl+Alt+C raised the panel over it.
- Panel look (2026-11-08): the Afiniti Spark theme (`mindmap/design_themes/spark_theme`) as CSS in `agent-panel.html`: Spark colours, 14 px cards with the resting `--shadow`, 10 px search box with a blue focus ring, blue hover border, colour-matched glow on the confirm buttons, blue to cyan logo tile as inline SVG; gold only for rewards. State (the maintainer, 2026-11-09, replacing a blinking dot): the dot is green for a working or open session, grey for a closed one, red for one asking. The whole card of a working session breathes: its background and a ring fade to green and back every 2.4 s (a plain blink of the dot was not seen from afar; a hard blink of whole cards, several at once, was rejected as too loud at the screen edge). A session whose own window shows a prompt waiting for an answer (a permission question or a dialog) pulses red, faster (1.2 s), so it stands out among working ones. Under reduced motion the card keeps a still green or red tint and ring, and the working dot is a hollow ring. The red state comes from `waitingFor`: Claude Code writes it into `~/.claude/sessions/<pid>.json` while `status` still says `busy`, and the panel reads it every 2 s. Before this such a session looked as if it were working. Fonts are Segoe UI (Manrope and Inter are not installed; bundling them was offered, not chosen yet). The Tk version (2026-11-07) had to replace shadows with borders and draw icons with PIL; that is why it was ported (see `mindmap/claude-plus-fa.md`, Decisions).
- Mascot (2026-11-09, the maintainer): a purple octopus from the maintainer's own sprite sheet, the header's logo (36 px, showing the most pressing state in the list) and on every card (38 px, on the left). It replaced, the same day, MindCopy's Knowledge Gremlin, whose detail turned to mush at 38 px; drawn SVG droplets were tried in between and rejected (too soft, then a superhero version that did not read). Mood by state: working reads a tablet (loop, 650 ms a frame), asking looks puzzled with a question mark (loop, 550 ms), open looks around and blinks once then rests 5 s (450 ms), closed sleeps without moving. The sheet's frames are separate poses, not in-betweens, so each holds about half a second; faster swapping looked jittery. One `requestAnimationFrame` timer drives every strip; each card starts at a random moment so they do not move in step; reduced motion shows frame 0 only (rules: `mindmap/mascot.md`). Every card shows the same octopus: the sheet has one character, so cards no longer look different from each other.
- Card rows (2026-11-08, the maintainer; path row removed 2026-11-09): title, whose tooltip is the full folder path (`where_of`: a WSL-distro session gets `\\wsl.localhost\<distro>` in front, `//` paths turn into backslashes), with the title in full above it when the title is cut (navy, after 400 ms of pointer movement, gone after 3 s, on leave, on a click or on scroll, per `tooltip.md`, which also rules out opening it on keyboard focus; a screen reader gets the path in the card's label). The path had its own row until 2026-11-09; dropping it makes cards smaller so more sessions fit, at the cost of telling same-titled sessions apart only by pointing. Search still matches the path. Then `ctx` bar + percent from `~/.claude/state/context/<sid>.json` (green < 50, gold < 80, red above, as on the status line; left out entirely when unknown) and on the right `hidden` / `headless` / `folder deleted` / age, joined by ` · `. Every part of that row but the flags keeps its width; the flags end in `…` when they do not fit, with the same tooltip showing them in full (a row wider than the card gave the list a horizontal scrollbar, 2026-11-08). Cards are 56 px high. The `(WSL)` tag is gone: the path shows it. The bottom strip shows `5h` and `week` bars from `rate_limits.json`; a figure whose `resets_at` has passed says *no figure yet*. Cards are kept and patched by id, never redrawn wholesale: open sessions change every 2 s, and a redrawn card drops the hover and the title's tooltip (this hid the tooltip in the first web build).
- `apply design.md` (2026-11-08, three passes) changed the panel: a message about one card shows under that card (an error stays until the next click or key, a success leaves after 5 s); a message about the whole panel floats above the bottom link, and a failed scan stays there in amber until a scan succeeds; the search has a × and Esc, searches title and full path, marks hits and turns the count into `matches/total`; a skeleton shows until the first scan (`scanned` in the state); the age moved to the title row; titles cut with … get a tooltip; every button has a custom tooltip (no `title`); cards are keyboard buttons (Enter or Space opens, Shift+F10 or the menu key opens the menu, arrows walk it); reduced motion stops all motion and draws the working dot as a ring; the closed dot and the bottom link were darkened for contrast. `statusline.py` now rounds halves up like the panel, so both show the same percent.
- Clicks (2026-11-07, the maintainer): a closed session opens only on a double click, so a stray click never starts one (a single click says "Double-click to open it.", held back 450 ms so a double click never shows it); an open session comes forward on a single click.
- A click on an open session raises its window instead of starting a second copy (2026-11-07), by the technique in `mindmap/desktop-apps.md` *Bringing another app's window forward* (`AttachConsole` + `GetConsoleWindow`, `GA_ROOTOWNER`, `SW_RESTORE` only if minimised, Ctrl+Tab through tabs). Tested: a minimised test session came back in front at its earlier size.
- Until 2026-11-07 the panel reserved the edge as an AppBar. The maintainer dropped that: it pushed desktop icons left and kept maximised browsers off the edge; they want it over them, covered by whatever window is active. It still registers and removes an AppBar once at start (why: `mindmap/desktop-apps.md` *Over the edge, not beside it*).
- The installers stop the panel through the named event `Local\claude-plus-fa-agent-panel-quit` before forcing it; one instance only (mutex `Local\claude-plus-fa-agent-panel`). The pattern is in `mindmap/desktop-apps.md` *Start, stop, one copy*; so is why every child gets a clean environment (`clean_env()` in the `.pyw`).
- Hook timeout is 3600 s because the dialog waits inside the hook. A detached child would be simpler but was killed when its parent ended in testing.
- Guard: if `ANTHROPIC_BASE_URL` is set the hook does nothing, so a GLM session hitting its own limit never relaunches itself.
- `--dangerously-skip-permissions` is added when the hook input's `permission_mode` is `bypassPermissions`, or when the field is missing.
- Hooks load at session start: open sessions need a restart after install. `statusLine` does not: open sessions picked it up live.
- Context state: `statusline.py` writes `~/.claude/state/context/<session_id>.json` (`{"used_percentage": n}`) on every refresh; `context-guard.py stop` reads it and keeps a `<session_id>.warned` flag. Without our status line the guard stays silent. The figure lags by one message.
- 90 % was chosen because auto-compaction fired at 966–979K tokens of a 1M window (15 of 15 past compactions, about 96.7 %); 95 % left too little room for the documentation pass.
- Status line input fields used: `model.display_name`, `context_window.used_percentage` (null before the first reply), `rate_limits.five_hour|seven_day.used_percentage` and `.resets_at` (epoch seconds).

## Tested (2026-10-01)
- Claude session resumed on GLM with history intact.
- Dialog Yes opens the window with the right command; No does nothing.
- Install into an empty fake profile, run twice: one hook entry, other settings untouched; real install leaves settings.json unchanged when already installed.
- Status line seen live in a real session: `Opus 5.5 · ctx 58% · 5h 38% 02:40 · week 42% Tue 07:00`; an existing foreign `statusLine` is left alone by the installer.
- Context guard (2026-10-02): simulated climb 85 → 91 (warns) → 93 (silent) → 3 (re-arms) → 92 (warns again); `stop_hook_active` and missing state stay silent. A live session wrote its state file. - Startup message (2026-10-02): silent without handoff.md; names the date and the files when present; reached the model in a real `glm -p` session (GLM-4.7-Flash then ignored it, a model weakness, not a hook failure). Installer keeps `resumed` and `started` as separate SessionStart entries.
- File announcement (2026-10-05): `claude -p` in a temp folder with handoff.md + memory.md: the startup hook's JSON reached Claude Code (`hook_response`), Claude read both files and opened with "Read handoff.md and memory.md from …". `/compact` on a resumed session: the `compact` hook's JSON arrived and the next reply named handoff.md by full path. The second line in a live terminal not yet seen; it appears after the first prompt of a session started after install.
- Agent Panel right-click (2026-11-07): Hide, Show hidden, Unhide and Delete tested on a throwaway profile (`USERPROFILE` pointed at a temp folder holding two fake sessions), so no real transcript was touched: the fake transcript, its folder and its file-history went to the Recycle Bin, the project's `CLAUDE.md` and `memory.md` stayed. ## Limits
- Windows only (WebView2, cmd).
- A short 429 that ends a turn also triggers the dialog.
- The old window stays open; close it yourself.
- Every project can fall back, so sensitive code can go to z.ai if you click Yes.
