# claude-plus-fa — memory

## Files and where they install
| Source | Installed to | Job |
|---|---|---|
| `glm.cmd` | `~/.local/bin` (on the user PATH) | runs `claude` against `https://api.z.ai/api/anthropic`, main model `glm-4.7-flash`, small model `glm-4.5-flash`. Shares `~/.claude`, so `glm --resume` sees every session |
| `glm-fallback.py` | `~/.claude/hooks` | `StopFailure` hook, matcher `rate_limit`. Silent unless the key file holds a real `CLAUDEX_KEY` (not empty, not the placeholder): without one, Yes would only send the conversation to z.ai to be refused. Shows a Yes/No dialog; on Yes opens `cmd /k glm --resume <sid> [--dangerously-skip-permissions] "<continue prompt>"` in the session's cwd |
| `statusline.py` | `~/.claude` | `statusLine` command: model · `ctx` bar · `5h` bar + reset time · `week` bar + reset day/time. Also writes `~/.claude/state/context/rate_limits.json` (the `rate_limits` object plus `at`, written to a `.tmp` and swapped in) for the Agent Panel. Bars green < 50 %, yellow < 80 %, red above. `5h`/`week` come from `rate_limits`, which only a claude.ai subscription sends, so GLM sessions show `ctx` alone |
| `prompt-recall.py` | `~/.claude/hooks` | `UserPromptSubmit` hook: writes the prompt to `~/.claude/state/context/<session_id>.prompt.json` (`{"prompt", "at"}`) and prints nothing, because a UserPromptSubmit hook's stdout is added to Claude's context. Skips prompts that start with `<task-notification>` or `<system-reminder>`: Claude Code delivers a finished background task through this hook as if the user had typed it, and it used to replace the real prompt on the status line (fixed 2026-10-20). `statusline.py` shows it in full under the bars as `› HH:MM  <prompt>`: whitespace collapsed, wrapped to the console width (read from `CONOUT$`, since Claude Code passes no width and stdout is a pipe; 120 if that fails), at most `PROMPT_LINES` = 12 lines, the last one ending in `…` when cut. Claude Code trims every status line, so the continuation indent starts with a colour code to survive the trim. Changed from a single cut line on 2026-10-07 at the user's request: the prompt must be readable in full |
| `context-guard.py` | `~/.claude/hooks` | one script, four modes: `stop` (Stop: at ≥ 90 % context, once per climb, exit 2 with the documentation steps; re-arms when usage falls under 50 %), `precompact` (PreCompact: stdout becomes extra compaction instructions), `resumed` (SessionStart matcher `compact`: tells Claude to read `handoff.md` and `memory.md` when present, then run the resume steps; the same session continues, so this is where the 90 % documents get read back), `started` (SessionStart matcher `startup|clear`: if the cwd has `handoff.md`, tells Claude its date and to read it and `memory.md` first; silent otherwise; `--resume` needs nothing because the conversation comes back). `resumed` and `started` answer in JSON: `systemMessage` tells the user which files will be read (or, after compaction, that no handoff.md was found), `additionalContext` tells Claude to read them and then name the files it read in one line |
| `agent-panel.pyw` | `~/.claude`, started by `pythonw.exe` from `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `ClaudePlusFA agent panel` | Windows app (pywebview showing `agent-panel.html` in WebView2, tray via `pystray`): every session, newest first, an ordinary window over the right edge of the work area, 280 logical px wide, not topmost: it reserves no space, so desktop icons and maximised windows keep their place and the active window covers it. `Ctrl+Alt+C` or the tray raises it when covered, hides it when it is in front, shows it when hidden. A click runs `claude --resume <id> --dangerously-skip-permissions` in a new console in the session's folder: `cmd /k` normally, PowerShell for a UNC folder (`\wsl.localhost\...`, cmd cannot stand in one), `wsl.exe --cd` for a session found inside a running WSL distro's own `~/.claude`. A single click raises an open session; a closed one opens on a double click |
| `agent-panel.html` | `~/.claude`, beside the `.pyw` | The panel's whole look and its input handling. Python pushes the state with `app.update(<json>)` (only when it changed) and the page calls `window.pywebview.api.<ready, click, open, set_hidden, close, delete, hide>`, each returning the line shown at the bottom |
| `install.py` / `install.cmd` | — | copies the files, adds `~/.local/bin` to the user PATH if missing, registers the hook in `~/.claude/settings.json` (backup `settings.json.before-claude-plus`), sets `statusLine` only if none exists or it is already ours, creates the key file with a placeholder if missing and prints a one-line optional note; it never opens Notepad (until 2026-10-28 it did, on every install and update, which read as if the key were required; everything but the GLM switch works without it) |

Branches (2026-10-06): `main` is the public branch, tracking `origin` = https://github.com/firatada-ctrl/claude-plus; it started as one squashed commit, "Initial public release". `history` is local only and holds the full development history up to that release (old commits carry personal paths and session links, so it is never pushed). Work on `main`. Every push needs the maintainer's approval; before one, scan what goes out for keys (the release was checked against the real z.ai key and the GitHub token, with no finding).

Public and personal behaviour (2026-10-06): one code base, published as `firatada-ctrl/claude-plus` under MIT. `context-guard.py` carries built-in steps (`WARN_STEPS`, `RESUME_STEPS`) in its `stop` and `resumed` messages. `~/.claude/claude-plus.local.json` with `{"rule": "<where your steps live>"}` replaces them with "run the ... steps in <rule>"; a missing, unreadable or non-object file falls back to the built-in steps. The installer never writes that file. The maintainer's copy points at the global CLAUDE.md, section "Never let unwritten knowledge accumulate", which holds a richer procedure (mindmap page, rules to propose). Two branches or two repos were rejected: every fix would have to be carried twice and the copies drift.

Uninstall (2026-10-07): `uninstall.cmd` / `uninstall.py` removes every hook whose command names one of the three scripts, keeps any other hook in the same event, drops events and `hooks` left empty, removes `statusLine` only when it names `statusline.py`, then deletes the five installed files and `~/.claude/state/context`. Backup first: `settings.json.before-claude-plus-uninstall`, written only when something changes. Kept on purpose: the key file, `claude-plus.local.json`, the install backup, and `~/.local/bin` on PATH (other tools live there). Tested in a fake profile (USERPROFILE override, install via `install.copy_files()` + `register_hook()` so the real registry PATH is untouched): with and without a foreign status line, a foreign Stop hook survived, a second run reported nothing to do. Never run it on the maintainer's own profile as a test.

Key file: `~/.claudex/profiles/glm/.env`, line `CLAUDEX_KEY="..."`. Never in this repo. The path is claudex's, so `claudex validate glm` works on it; glm.cmd itself does not need claudex.

## Behaviour
- Session panel (2026-11-07): sessions are the `<uuid>.jsonl` files directly under `~/.claude/projects/<folder>/` (subagent and set-aside transcripts excluded), plus the same under each WSL distro that is already running (`wsl -l --running`; the panel never starts one). Title: the last `custom-title` (`/rename`), else the last `ai-title`, else the first real prompt. A session must be resumed from the folder its transcript is filed under, and a session that moved (`/cd`) lists several `cwd`s, so the panel picks the `cwd` whose slug (every non-alphanumeric character as `-`) equals the folder name. Open sessions come from `~/.claude/sessions/<pid>.json` (`sessionId`, `status` busy/idle/shell, `name`) when that pid is alive. Parsed results are cached in `~/.claude/state/agent-panel/cache.json` by mtime and size; a rescan every 15 s takes about 0.05 s.
- The panel was called "session panel" (`session-panel.pyw`) until it became the Agent Panel on 2026-11-07, at Fırat's request. The installers stop a copy under either name and delete the old file, sign-in entry and state folder.
- Right-click menu (2026-11-07, Fırat's spec): Hide / Unhide, Close (open sessions only), Delete. The menu is HTML inside the panel (a web page cannot draw outside its window), opened at the pointer and kept inside the panel; Delete is red on a pale red hover. It closes on Escape, on a click outside (that click does nothing else), on scroll and on focus loss. The native menu was rejected (Fırat, 2026-11-08: it ignores the theme). Hidden ids live in `~/.claude/state/agent-panel/hidden.json`; Hidden sessions, sessions whose folder is gone and headless runs (`entrypoint` `sdk-cli` in the transcript: a `claude -p` that another session started, e.g. tech news calling the Topview MCP; 2026-11-08, Fırat) stay out of the main list and the header count; a headless card says `headless` and its menu has no Hide; the greyed link *Show hidden, deleted and headless (n)* in the strip under the list adds a HIDDEN, DELETED AND HEADLESS section after the main list and scrolls to it. Cards there are not greyed; their second line says `hidden` or `folder deleted` (Fırat, 2026-11-07: greyed cards inside the main list read as clutter; the user's word is "deleted", not "missing"). Open/working dots are refreshed every 2 s from `~/.claude/sessions/<pid>.json` alone (the full transcript scan stays at 15 s), so a session closed in its own terminal loses its dot within 2 s. Close and Delete confirm in two steps beside the control, per `mindmap/table.md` *Delete confirmation* (2026-11-08, replacing two modal dialogs): the menu turns into a small card with the question, one sentence on what happens, Cancel (focused, the default) and *Yes, close* / *Yes, delete*. Delete refuses an open session and a session stored inside WSL (a network path has no Recycle Bin), then moves the transcript, its `<id>/` folder and `file-history/<id>/` to the Recycle Bin with `SHFileOperationW` (`FOF_ALLOWUNDO`). Project files and the project's auto memory are never touched. Close sends `WM_CLOSE` to the session's window when no other open session shares it, otherwise ends the process; the transcript stays.
- Tested 2026-11-07: work area back to the full 1920 px with the panel running; a maximised window spans the full width and covers the panel; Ctrl+Alt+C raised the panel over it.
- Panel look (2026-11-08): the Afiniti Spark theme (`mindmap/design_themes/spark_theme`) as CSS in `agent-panel.html`: Spark colours, 14 px cards with the resting `--shadow`, 10 px search box with a blue focus ring, blue hover border, colour-matched glow on the confirm buttons, blue to cyan logo tile as inline SVG; gold only for rewards, so a working session is blue, an open one green. Fonts are Segoe UI (Manrope and Inter are not installed; bundling them was offered, not chosen yet). The Tk version (2026-11-07) had to replace shadows with borders and draw icons with PIL; that is why it was ported (see Decisions).
- Card rows (2026-11-08, Fırat): title; the full folder path (`where_of`: a WSL-distro session gets `\\wsl.localhost\<distro>` in front, `//` paths turn into backslashes), cut in the middle so the drive and the last folder stay, with a tooltip of the whole path when cut (navy, after 400 ms of pointer movement, gone after 3 s, on leave, on a click or on scroll, per `tooltip.md`); then `ctx` bar + percent from `~/.claude/state/context/<sid>.json` (green < 50, gold < 80, red above, as on the status line; left out entirely when unknown) and on the right `hidden` / `headless` / `folder deleted` / age, joined by ` · `. Every part of that row but the flags keeps its width; the flags end in `…` when they do not fit, with the same tooltip showing them in full (a row wider than the card gave the list a horizontal scrollbar, 2026-11-08). Cards are 72 px high. The `(WSL)` tag is gone: the path shows it. The bottom strip shows `5h` and `week` bars from `rate_limits.json`; a figure whose `resets_at` has passed shows `--`. Cards are kept and patched by id, never redrawn wholesale: open sessions change every 2 s, and a redrawn card drops the hover and the path tooltip (this hid the tooltip in the first web build).
- Clicks (2026-11-07, Fırat): a closed session opens only on a double click, so a stray click never starts one (a single click says "Double-click to open it."); an open session comes forward on a single click.
- A click on an open session raises its window instead of starting a second copy (2026-11-07): `AttachConsole(pid)` then `GetConsoleWindow`, which under Windows Terminal is a `PseudoConsoleWindow` whose root owner (`GetAncestor(..., GA_ROOTOWNER)`) is the terminal window; then `SW_RESTORE` only if it is minimised (it returns to its earlier size and place; Fırat asked for that, not maximised) and `SetForegroundWindow` (a lone Alt press if Windows refuses the foreground). Each session here sits in its own terminal window titled with its name; when a window holds several tabs, Ctrl+Tab steps through them until the title shows the session's name. Tested: a minimised test session came back in front at its earlier size.
- Until 2026-11-07 the panel reserved the edge as an AppBar (`SHAppBarMessage`). Fırat dropped that: it pushed desktop icons left and kept maximised browsers off the edge; he wants it over them, covered by whatever window is active. It still registers and removes an AppBar once at start, which makes Windows drop an edge left reserved by an older copy that was killed.
- (history) AppBar space leaks when the panel is killed: Windows keeps the old reservation. The panel re-docks 2.5 s after start, which clears it, and the installers stop it through the named event `Local\claude-plus-fa-agent-panel-quit` before forcing it. One instance only (mutex `Local\claude-plus-fa-agent-panel`).
- Hook timeout is 3600 s because the dialog waits inside the hook. A detached child would be simpler but was killed when its parent ended in testing.
- Guard: if `ANTHROPIC_BASE_URL` is set the hook does nothing, so a GLM session hitting its own limit never relaunches itself.
- `--dangerously-skip-permissions` is added when the hook input's `permission_mode` is `bypassPermissions`, or when the field is missing.
- Hooks load at session start: open sessions need a restart after install. `statusLine` does not: open sessions picked it up live.
- Context state: `statusline.py` writes `~/.claude/state/context/<session_id>.json` (`{"used_percentage": n}`) on every refresh; `context-guard.py stop` reads it and keeps a `<session_id>.warned` flag. Without our status line the guard stays silent. The figure lags by one message.
- 90 % was chosen because auto-compaction fired at 966–979K tokens of a 1M window (15 of 15 past compactions, about 96.7 %); 95 % left too little room for the documentation pass.
- Status line input fields used: `model.display_name`, `context_window.used_percentage` (null before the first reply), `rate_limits.five_hour|seven_day.used_percentage` and `.resets_at` (epoch seconds).

- Dialog Yes opens the window with the right command; No does nothing.

- Startup message (2026-10-02): silent without handoff.md; names the date and the files when present; reached the model in a real `glm -p` session (GLM-4.7-Flash then ignored it, a model weakness, not a hook failure). Installer keeps `resumed` and `started` as separate SessionStart entries.

- Prompt recall (2026-10-06): Claude Code 2.1.287 splits the status line's stdout into lines and drops empty ones, so a second line shows (checked in the binary, `sGn`); `UserPromptSubmit` input carries the text as `prompt`. A real `claude -p` session wrote the prompt file; the hook's stdout stayed empty. The second line in a live terminal not yet seen; it appears after the first prompt of a session started after install.
- Agent Panel right-click (2026-11-07): Hide, Show hidden, Unhide and Delete tested on a throwaway profile (`USERPROFILE` pointed at a temp folder holding two fake sessions), so no real transcript was touched: the fake transcript, its folder and its file-history went to the Recycle Bin, the project's `CLAUDE.md` and `memory.md` stayed. ## Limits
- Windows only (MessageBoxW, cmd).
- A short 429 that ends a turn also triggers the dialog.
- The old window stays open; close it yourself.
- Every project can fall back, so sensitive code can go to z.ai if you click Yes.

## Decisions
- 2026-11-07, Agent Panel built as a Tk window, not a web view: about 25 MB against 100 MB or more for an always-open panel, no .NET bridge to install. Rejected: pywebview with WebView2.
- 2026-11-08, ported to pywebview + WebView2 (Fırat agreed the boundary: behaviour 1:1; drawing, menu and the two-step confirm replaced). Tk could not draw the Spark look: jagged corners, no shadow, a native menu, every fix hand drawing. Cost measured on 2026-11-08: about 210 MB private memory (pythonw with .NET 68 MB, five WebView2 processes 142 MB). The general rule is `mindmap/desktop-apps.md`.
- 2026-11-08, headless runs are not nested under the session that started them (Fırat agreed): the transcript does not record its parent, so linking needs a search of the parent's transcript (tech news's is 278 MB) or a folder-and-time guess, and the runs are rarely opened. They stay in the set-aside section.
- 2026-11-07, a click on an open session restores its window (`SW_RESTORE` only if minimised) and raises it. Maximising was tried first and rejected by Fırat: he wants the window back where it was.
- 2026-11-07, Delete goes to the Recycle Bin, never a permanent delete, so a slip can be undone (Fırat's choice).
- 2026-11-07, package display name `claude-plus-fa` (FA for Fırat Ada); file names such as `claude-plus.local.json` and the backup suffixes keep the old name so existing installs do not break.
